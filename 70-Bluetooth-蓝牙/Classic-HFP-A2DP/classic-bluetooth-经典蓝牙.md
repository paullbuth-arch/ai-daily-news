# 经典蓝牙：HFP / A2DP / AVRCP / SPP

**一句话结论（20% 核心）**：经典蓝牙（BR/EDR）管两件事——通话（HFP，双向低延迟语音）和音乐（A2DP，单向高质量音频）。WQ7036AX 是双模蓝牙芯片，经典蓝牙和 BLE 可以同时工作，共享同一根天线。reGlasses 的通话和音乐播放全靠经典蓝牙。

---

## 第一层：核心认知（必须先看懂）

### 1.1 费曼类比：电话线 vs 音响线 vs 对讲机

- **HFP（免提通话）** = 电话线：双向通话，双方同时说话，音质一般但延迟极低（<30ms），否则对话很难受
- **A2DP（音乐播放）** = 音响线：单向传输，手机→耳机，音质好（44.1/48kHz），但缓冲大导致延迟高（~150ms）
- **AVRCP（媒体控制）** = 遥控器：切歌、暂停、调音量，只传控制命令不传音频
- **SPP（串口仿真）** = 无线对讲机：传任意二进制数据，没有固定格式，类似无线版 UART

**为什么通话和音乐要用不同的协议？** 因为通话要求低延迟（你说话对方马上听到），音乐要求高音质（44.1kHz 立体声）。无法在一个协议里同时满足，所以分成了 HFP 和 A2DP。

### 1.2 蓝牙协议栈：经典蓝牙在哪一层？

```
应用层:    HFP/A2DP/AVRCP/SPP  ← 这是你要学的 Profile
              │
协议层:    RFCOMM / L2CAP / SDP   ← 协议栈自动处理
              │
链路层:    ACL (数据) / SCO (语音)  ← 两种物理链路
              │
物理层:    2.4GHz 射频              ← WQ7036AX 的 BCORE 负责
```

**两种物理链路的区别**（这是理解经典蓝牙的核心）：

| 链路类型 | 全称 | 用途 | 特点 |
|---------|------|------|------|
| **ACL** | Asynchronous Connection-Less | 数据、音乐、控制命令 | 有重传保证可靠，延迟高 |
| **SCO/eSCO** | Synchronous Connection-Oriented | 语音通话 | 预留时隙保证低延迟，无重传 |

**关键理解**：HFP 通话走 SCO 链路（低延迟，丢了就丢了，不等重传），A2DP 音乐走 ACL 链路（可靠传输，但缓冲大导致延迟高）。这就是为什么通话延迟低但音质差，音乐音质好但延迟高。

### 1.3 四大 Profile 深度对比

| Profile | 底层链路 | 音频编码 | 采样率 | 方向 | 延迟 | reGlasses 场景 |
|---------|---------|---------|--------|------|------|---------------|
| **HFP** | SCO/eSCO | CVSD / mSBC | 8/16 kHz | 双向 | ~30ms | 微信通话、电话 |
| **A2DP** | ACL | SBC / AAC / LDAC | 44.1/48 kHz | 单向 | ~150ms | 听音乐、导航播报 |
| **AVRCP** | ACL | 无音频 | — | 双向 | <10ms | 按键切歌、调音量 |
| **SPP** | ACL | 无音频 | — | 双向 | <50ms | 传自定义数据（已较少用） |

### 1.4 双模蓝牙的共存机制

WQ7036AX 是双模芯片，**经典蓝牙和 BLE 可以同时工作**。它们共享 2.4GHz 天线，通过时分复用（TDM）交替使用射频：

```
时间轴: | BLE | 经典蓝牙 | BLE | 经典蓝牙 | BLE | ...
        | 广播 | A2DP 音乐 | 连接 | HFP 通话 | 广播 | ...
```

**实际影响**：经典蓝牙和 BLE 同时工作时，各自的带宽都会下降。reGlasses 需要在通话+BLE 数据传输之间做带宽分配。详见 [[reglasses-bandwidth-reGlasses带宽约束]]。

### 1.5 如果只记得一件事

> 经典蓝牙 = 两种物理链路（ACL 管数据/音乐，SCO 管通话）+ 四大 Profile（HFP 通话、A2DP 音乐、AVRCP 遥控、SPP 数据）。WQ7036AX 的双模蓝牙可以同时工作，但共享带宽。

## 第二层：实战理解

### 2.1 HFP 通话的完整音频链路

```
手机端                            WQ7036AX 端
  │                                  │
  │ 麦克风采集                       │
  │   ↓                              │
  │ CVSD/mSBC 编码                   │
  │   ↓                              │
  │── SCO/eSCO 空中发送 ────────────→│
  │                                  │ 收到→解码→I2S→功放→扬声器
  │                                  │     (你听到对方的声音)
  │                                  │
  │←── SCO/eSCO 空中发送 ────────────│
  │                                  │ PDM 麦→DSP(降噪/AEC)→编码
  │ 收到→解码→扬声器                  │     (你的声音发给对方)
  │     (对方听到你的声音)            │
```

**AEC（回声消除）在 HFP 中极其重要**：你的扬声器播放的声音如果被你的麦克风重新采集，对方会听到自己的回声。WQ7036AX 的 DCORE 做 AEC 处理，消除扬声器→麦克风的回声路径。

### 2.2 WQ7036AX 经典蓝牙的代码位置

BCORE 固件（封闭源码）负责蓝牙底层协议栈和射频。ACORE 负责应用层控制，代码在：

```
wqcore/components/bluetooth/host/bbb/inc/wq_bth_api.h  ← 蓝牙主机 API
wq-adk/components/bt_service/api/bt_srv_api.h          ← 蓝牙服务层 API
```

应用层调用示例（简化）：
```c
// 发起 HFP 通话连接
bt_srv_hfp_connect(peer_addr);

// 注册通话状态回调
bt_srv_register_hfp_callback(on_call_state_change);

void on_call_state_change(hfp_call_state_t state) {
    switch (state) {
    case HFP_CALL_ACTIVE:
        // 通话中，调整音频路由到 I2S→功放
        aud_sv_set_route(AUDIO_ROUTE_I2S_SPEAKER);
        break;
    case HFP_CALL_IDLE:
        // 通话结束，恢复正常
        aud_sv_set_route(AUDIO_ROUTE_NONE);
        break;
    }
}
```

### 2.3 常见坑（附排查方法）

| 问题 | 现象 | 排查方法 | 根因 |
|------|------|---------|------|
| HFP+A2DP 同时用时音质变差 | 音乐播放中接电话，音质骤降 | 看带宽是否超限 | SCO 预留了固定时隙，ACL 可用带宽被压缩 |
| SCO 链路断开 | 通话中突然没声音 | 看 HCI log，检查监督超时 | 距离太远/干扰大，SCO 无重传，断了就断了 |
| A2DP 音频延迟大 | 看视频时画面和声音不对 | 测量实际延迟 | A2DP 默认缓冲 100-200ms，需要减少缓冲或用低延迟编码 |
| 配对后无法连接 HFP | 只连上了 A2DP，HFP 连不上 | 检查手机端是否同时支持 HFP 和 A2DP | 手机只配对了 A2DP，HFP 需要单独建立 SCO 连接 |
| CVSD vs mSBC 编码差异 | 宽带通话 vs 窄带通话音质差别大 | 看 HCI 协商结果 | mSBC 是 16kHz 宽带，CVSD 是 8kHz 窄带 |

### 2.4 在 reGlasses 项目中怎么用

reGlasses 的经典蓝牙主要用于两个场景：

1. **免提通话**（HFP）：眼镜当蓝牙耳机用，麦克风在眼镜上，扬声器也在眼镜上
2. **音乐播放**（A2DP）：手机播放音乐，眼镜接收并播放到双扬声器
3. **按键控制**（AVRCP）：眼镜上的按键切歌、暂停

WQ7036AX 的 BCORE 固件实现了完整的协议栈，ACORE 上你只需要调用 bt_service API。**但理解底层的 SCO/ACL 链路区别、编码格式、延迟特性，对排查通话卡顿、音质差等问题至关重要。**

## 第三层：深入扩展

### 3.1 HFP 的编码器：CVSD vs mSBC

| 编码 | 采样率 | 码率 | 音质 | 延迟 |
|------|--------|------|------|------|
| **CVSD** | 8 kHz | 64 kbps | 窄带（电话音质） | 极低 |
| **mSBC** | 16 kHz | 64 kbps | 宽带（微信音质） | 低 |

WQ7036AX 支持 mSBC（宽带语音），在 BLE 连接时协商使用。如果手机不支持 mSBC，回退到 CVSD。

### 3.2 A2DP 的编码器：SBC vs AAC

| 编码 | 码率 | 音质 | 兼容性 |
|------|------|------|--------|
| **SBC** | 328 kbps | 基础 | 所有蓝牙设备都支持 |
| **AAC** | 256 kbps | 优于 SBC | iPhone 默认 |
| **LDAC** | 330/660/990 kbps | 接近无损 | 索尼设备 |

WQ7036AX 主要用 SBC（兼容性最好），A2DP 规范要求所有设备必须支持 SBC。

### 3.3 常见问题

- **为什么通话和音乐不能同时高品质？** 因为 SCO 和 ACL 共享蓝牙带宽（最大 3 Mbps），SCO 预留了固定时隙给语音，剩下的才给 ACL 传音乐。
- **SPP 现在还常用吗？** 在 BLE 普及后，SPP 逐渐被 BLE GATT 替代。BLE 更省电，且 GATT 的结构化数据比 SPP 的流式数据更适合现代应用。
- **经典蓝牙和 BLE 能同时连接同一个手机吗？** 能。WQ7036AX 就是这样用的：BLE 传控制+音频数据，经典蓝牙通话+音乐。
