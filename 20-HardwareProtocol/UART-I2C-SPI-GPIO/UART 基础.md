# UART 基础

**一句话结论（20% 核心）**：UART 是最简单的通信协议——两根线，没有时钟，约定好语速（波特率），一个人说（TX）一个人听（RX）。WQ7036AX 和 V881 之间的所有通信都跑在 UART 上。

---

## 第一层：核心认知（必须先看懂）

### 1.1 费曼类比：两个人用对讲机

UART 就像两个人用对讲机通话：
- 约定好**语速**（波特率 = 115200，每秒说 115200 个 bit）
- A 的**嘴巴（TX）**对着 B 的**耳朵（RX）**
- A 的**耳朵（RX）**听着 B 的**嘴巴（TX）**
- 没有第三者提供节拍（**异步通信**——没有时钟线，全靠约定）

```
WQ7036AX                      V881
  TX (GPIO50) ──────────────→ RX
  RX (GPIO51) ←────────────── TX
  GND ─────────────────────── GND
```

**关键理解**：交叉连接！A.TX → B.RX，A.RX ← B.TX。TX 是"嘴巴"，RX 是"耳朵"，嘴巴对耳朵。

### 1.2 一个字节怎么传？

```
空闲状态（线拉高）
    │
    ├── Start bit（拉低 1 个 bit 时间）── "我要开始说话了"
    ├── D0（最低位）
    ├── D1
    ├── D2
    ├── D3
    ├── D4
    ├── D5
    ├── D6
    ├── D7（最高位）
    ├── Stop bit（拉高 1 个 bit 时间）── "我说完了"
    │
空闲状态（线拉高）
```

**reGlasses 的配置（记这个就行）**：115200 波特率，8 个数据位，无校验，1 个停止位——简称 **115200-8N1**。

### 1.3 为什么叫"异步"？

因为没有时钟线！发送方和接收方**必须预先约定相同的波特率**。接收方通过 Start bit 的下降沿来确定采样的起始时刻，然后按约定频率采样后续的 bit。

**费曼类比**：两个人约好"每分钟说 100 个字"。说到某个词时开始计时，后面按节奏听。如果一个人说 100 字/分，另一个人按 120 字/分听——全乱套了。

### 1.4 核心概念速查表

| 术语 | 中文 | 一句话 |
|---|---|---|
| Baud Rate | 波特率 | 每秒传多少个 bit，收发双方必须一致 |
| TX | 发送 | 我的嘴巴 |
| RX | 接收 | 我的耳朵 |
| Start Bit | 起始位 | 拉低信号，告诉对方"我要说话了" |
| Stop Bit | 停止位 | 拉高信号，"我说完了" |
| LSB First | 低位先发 | 数据位从 D0（最低位）开始发 |
| FIFO | 硬件缓冲队列 | 先入先出，CPU 往里写，硬件自动一位一位发 |
| 8N1 | 8数据位+无校验+1停止位 | 最常见的 UART 配置 |

### 1.5 如果只记得一件事

> UART = 两根线（TX/RX 交叉连接） + 约定波特率 + Start bit 开始 + 8 个数据位 + Stop bit 结束。WQ7036AX 和 V881 之间用 115200-8N1 通信。

## 第二层：实战理解

### 2.1 WQ7036AX 的 UART 是怎么工作的？

SDK 中 UART 驱动位于 `wqcore/driver/uart/`，核心 API：

```c
// 初始化 UART 端口
wq_uart_init(WQ_UART_PORT_1);  // 使能时钟、配置引脚、设置波特率

// 发送数据（非阻塞，放入发送队列后立即返回）
wq_uart_write(WQ_UART_PORT_1, data, len, tx_done_callback);

// 注册接收回调（中断驱动，收到数据自动调用）
wq_uart_register_rx_callback(WQ_UART_PORT_1, rx_buffer, buf_size, rx_callback);
```

**数据是怎么发出去的？**

```
你的代码调用 wq_uart_write()
    │
    ├── 如果 FIFO 有空位 → 直接写入 FIFO → 硬件自动按位发出
    └── 如果 FIFO 满了 → 把数据排入软件队列 → 开 TX 中断
            │
            └── FIFO 空了触发中断 → 从队列取下一块数据 → 写入 FIFO
```

**数据是怎么收到的？**

```
UART 硬件检测到 Start bit
    │
    ├── 按波特率采样 8 个数据位 → 拼成一个字节 → 放入 RX FIFO
    └── RX FIFO 达到阈值 → 触发中断 → ISR 把字节拷到环形缓冲区
            │
            └── 调用你注册的 rx_callback，通知上层"有数据了"
```

### 2.2 FIFO 是什么？为什么需要它？

**费曼类比**：FIFO 就像一个**传送带缓冲区**。你往传送带前端放包裹，传送带自动把包裹送到后端发出。如果没有 FIFO，CPU 每发一个字节都要等上一个字节完全发完——这浪费 CPU 时间。

WQ7036AX 的 UART 有 **16 字节硬件 FIFO**。CPU 可以一次写 16 个字节到 FIFO，然后去做别的事，硬件自动一位一位发出去。

### 2.3 常见坑

| 问题 | 现象 | 根因 |
|---|---|---|
| 波特率不匹配 | 收到乱码或收不到数据 | 双方波特率不一致，或时钟源配置错误 |
| 未交叉连接 | 完全收不到数据 | TX 接了 TX，RX 接了 RX（应该 TX→RX） |
| 中断未使能 | 数据收不到或发不出去 | 忘记使能 UART 中断 |
| FIFO 溢出 | 数据丢失 | 接收数据速度 > 处理速度，FIFO 满了 |

### 2.4 项目中的实际应用

WQ7036AX 的 UART1 连接 V881，上层跑着应用层命令协议。所有手机转发的指令（拍照、录像、TOF 等）都通过这条链路到达 V881。

在 SDK 中搜索 `app_uart_cmd` 可以找到命令帧的解析代码。

## 第三层：深入扩展

### 3.1 UART vs I2C vs SPI 对比

| | UART | I2C | SPI |
|---|---|---|---|
| 线数 | 2 (TX+RX) | 2 (SDA+SCL) | 4 (MOSI/MISO/SCK/CS) |
| 同步/异步 | **异步**（无时钟线） | 同步（SCL 时钟线） | 同步 |
| 寻址 | 无（点对点） | 7-bit 地址寻址 | 片选 CS |
| 速度 | 115200 bps（典型） | 100k/400k bps | 数十 MHz |
| 全双工/半双工 | 全双工 | 半双工 | 全双工 |
| reGlasses 用途 | **连 V881（命令+数据）** | 连 ELM2713、充电 IC | 未使用 |

### 3.2 为什么 UART 速度上不去？

UART 的异步特性意味着：接收方必须用**自己的时钟**去采样对方的信号。如果双方时钟有偏差，bit 采样点会逐渐漂移。波特率越高，漂移的影响越大。所以 UART 通常不超过几 Mbps，再快就必须用同步协议（如 SPI）。

### 3.3 常见面试题

- **UART 为什么叫"异步"？** 因为没有时钟线，双方靠约定的波特率自行采样。
- **Start bit 的作用？** 让接收方知道"传输开始了"，同时用下降沿校准采样时刻。
- **波特率 115200 时，一个 bit 占多少时间？** 1/115200 ≈ 8.68 微秒。
- **如果双方波特率相差 2%，能正常通信吗？** 10 个 bit 后偏差 20%，Stop bit 可能采样错误，不可靠。

|---|---|---|

| Baud Rate | 波特率 | 每秒传输的 bit 数 |
