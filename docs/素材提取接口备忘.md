# 素材提取接口备忘

2026-10-14 实测记录。三个平台取原图/原视频的可用路径、字段位置、噪音源和坑。

**背景**：素材导入原来的做法是"抓分享页 HTML 再正则捞 CDN 链接"。实测下来
这条路对小红书会连评论头像一起捞进来，对抖音已经完全失效（分享页里根本没有
媒体地址）。下面是逐个平台重新验过的做法。

---

## 小红书 🟢 最稳

**全程不需要签名、不需要登录。**

```
分享链接（xhslink.cn/… 或 xiaohongshu.com/…）
  → 跟随跳转拿 HTML
  → 解析 __INITIAL_STATE__
  → 只读 noteData.data.noteData
  → imageList[].fileId
  → https://sns-img-qc.xhscdn.com/{fileId}       ← 原图
```

**为什么不能用正则捞**：整页 HTML 里的 CDN 链接混杂着
`commentData.comments[].user.image`（评论头像）和主题图标。
只读 `noteData.data.noteData.imageList` 才能一个杂图都不带。

**原图 vs 平台给的地址**（实测对比同一张图）：

| 来源 | 尺寸 | 水印 | 签名 | 过期 |
|---|---|---|---|---|
| `imageList[].infoList[H5_DTL]` / `[].url` | 1080×1440 | **有**小红书水印 | 需要 | **短 TTL，会 403** |
| `https://sns-img-qc.xhscdn.com/{fileId}` | **1200×1600** | **无** | **不需要** | **不过期** |

镜像域名（内容一致，可互为备份）：
`sns-img-qc.xhscdn.com` / `sns-img-bd.xhscdn.com` / `ci.xiaohongshu.com`

**两个必须处理的解析坑**：
1. SSR 里混着**裸的 JS `undefined`**，直接 `json.decode` 会炸。要按字符扫描、
   跳过字符串内部地替换成 `null`。
2. `__INITIAL_STATE__` 后面那个 JSON 值里含花括号和转义引号，
   **不能用正则配到尾**，要按括号配平扫描并跳过字符串内部。

**视频笔记**：`note.video.media.stream.{h264,h265}[].masterUrl`，
按 `videoBitrate` 从高到低排。

代码：`lib/services/xiaohongshu_note_parser.dart`（纯函数，9 个单测）

## 闲鱼 🟢 稳

**不需要登录**（游客态可用）。

```
短链 m.tb.cn/xxx
  → HTML 里有 var url = '…itemId=1089795871579…'   ← 纯字符串提取
  → mtop 接口 mtop.taobao.idle.awesome.detail
```

**mtop 调用参数**（这几个值错了就会被风控拦）：

| 参数 | 值 |
|---|---|
| api | `mtop.taobao.idle.awesome.detail` |
| appKey | **`12574478`** |
| jsv | `2.7.3` |
| sign | `md5(token & t & appKey & data)` |

流程：第一次请求（无 token）会下发 `_m_h5_tk` cookie 并返回
`FAIL_SYS_TOKEN_EMPTY`；取 token（`_m_h5_tk` 里 `_` 之前那段）后带签名重发，
返回 `SUCCESS::调用成功`。

**商品图位置**（精确路径，别用正则全网捞）：

```
flowData.body.sections[0].components[6].data.imageInfos[].url
→ http://img.alicdn.com/bao/uploaded/iX/…/O1CN01…_!!…-0-xy_item.jpg
```

**会混进来的杂图**（都要排除）：
`flowData.floating.components[1].data.avatarUrl`（卖家头像）、
`…userInfo.levelTags[].iconUrl`（等级图标）、`sellerDO.idleFishCreditTag.iconUrl`
（信用标签）、`itemDO.charitableTag.iconUrl`、`secuGuide.secuIcon`、
`sellerItems[].iconUrl`。

**易错点**：`itemDO.images` 是**空的**，别以为没图就放弃；
api 名用错（比如 `idle.pc.detail`）会直接吃 `RGV587_ERROR` 风控。

代码：`lib/services/ecommerce_material_import_service.dart` 的
`_fetchGoofishDetail` / `_goofishImageUrls`（原本就是对的，未改动）

## 抖音 🟡 需要 WebView

**没有免签名的 HTTP 路径**，这是平台主动封的，不是找不到：

```
直接调 API        → 403  Blocked by ArgusSecurityPlugin Uifid Not Found
经典公开接口       → HTTP 200 但 0 字节（v2/iteminfo，已被摘空）
分享页 _ROUTER_DATA → 只有页面配置和 itemId，无媒体地址
分享页 _SSR_DATA    → {"data":{}} 空壳
桌面站 HTML        → 72KB JS 空壳，play_addr / url_list / RENDER_DATA 全 0
无头浏览器渲染分享页 → "抱歉出错了 请尝试在抖音内观看"
```

**唯一稳的路子：让页面自己的 JS 去算签名。**

```
1. WebView 渲染 https://www.douyin.com/video/{aweme_id}
   （移动版 m.douyin.com/share/video/… 实测是空白页，必须桌面站）
2. 等 <video> 挂上来，读它的 src：
   https://m.douyin.com/aweme/v1/playwm/?video_id=v0200fg…&ratio=720p&line=0
3. 拼无水印端点：
   https://aweme.snssdk.com/aweme/v1/play/?video_id={vid}&ratio=1080p&line=0
   → 302 → 直接是 MP4（实测 HTTP 200 / video/mp4 / 3.5MB）
```

**为什么 `play` 就是无水印**：抖音在 CDN 上**同时存了两份文件**，实测两者
302 到的路径完全不同：

```
playwm → video/tos/cn/tos-cn-ve-15/oguMsQEc1PADJjtOBziiglBCAZAeEp8EIifbCx
play   → video/tos/cn/tos-cn-ve-15/oUXtVxviBEjtcOzlAbiQCbeCjBfz1DAIiTguAZ
```

所以这不是"抹掉水印"，是取平台自己提供的干净副本。

**可用播放主机**（互为备份）：
`aweme.snssdk.com` / `www.iesdouyin.com` / `api-hl.amemv.com`
（`aweme-eagle.snssdk.com` 已失效，404）

**为什么不用移植 `a_bogus` 签名**：那段是抖音混淆 JS 的反推实现，
钉死在某个 SDK 版本（参考实现里写的是 `sdk 1.0.1.19-fix.01`），
抖音一升级就得重推一遍。让页面自己算签名，则抖音更新时页面 JS 自己会跟上，
我们不需要维护任何签名代码。

代码：`lib/services/douyin_share_resolver.dart`（纯逻辑，8 个单测）
—— WebView 只负责供应 `<video>` 的 `src` 字符串。

## 稳定性小结

| 平台 | 依赖 | 会怎么坏 | 坏了怎么办 |
|---|---|---|---|
| 小红书 | SSR 结构 + CDN 路径 | 改版后字段路径变 | 更新 `parseHtml` 里的取值路径 |
| 闲鱼 | mtop 固定签名公式 | 基本不会坏 | — |
| 抖音 | 浏览器渲染 + `play` 端点 | 端点下线 | 换备份主机；`video_id` 的取法不用改 |
