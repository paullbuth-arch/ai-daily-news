# 便携构建环境与 APK 构建

这份说明记录当前这台机器实际成功构建 APK 的方式，并把它固化成项目内脚本。

## 之前是怎么构建 APK 的

成功构建时用的是：

- Flutter SDK：`G:\flutter`，版本 `3.29.0`
- JDK：`D:\V881\padtest\dev_env\jdk-17.0.13+11`
- Android SDK：`D:\V881\padtest\dev_env\android-sdk`
- Android platform：`android-35`
- Android NDK：`27.0.12077973`
- Gradle wrapper：`8.10.2`
- Android Gradle Plugin：`8.7.3`
- Kotlin：`2.2.0`

当时执行的核心命令等价于：

```powershell
$env:JAVA_HOME='D:\V881\padtest\dev_env\jdk-17.0.13+11'
$env:ANDROID_HOME='D:\V881\padtest\dev_env\android-sdk'
$env:ANDROID_SDK_ROOT=$env:ANDROID_HOME
$env:Path="$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\cmdline-tools\latest\bin;$env:Path"
& 'G:\flutter\bin\cache\dart-sdk\bin\dart.exe' 'G:\flutter\bin\cache\flutter_tools.snapshot' build apk --release
```

现在推荐改用项目内脚本：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_apk.ps1
```

构建成功后的 APK 在：

```text
build\app\outputs\flutter-apk\app-release.apk
```

## 新电脑上推荐的目录结构

把环境目录放在项目同级，最省事：

```text
任意工作目录\
  dev_env\
    android-sdk\
    flutter\
    jdk-17.0.13+11\
  ipad_boss_app\
    tools\
      build_apk.ps1
      check_build_env.ps1
```

脚本会按顺序自动找：

1. `项目根目录\dev_env`
2. `项目根目录\..\dev_env`
3. `D:\V881\padtest\dev_env`
4. `FLUTTER_HOME` / `JAVA_HOME` / `ANDROID_HOME`

所以你把 `dev_env` 放在项目旁边，换电脑后不用改代码。

## 先检查环境

```powershell
powershell -ExecutionPolicy Bypass -File tools\check_build_env.ps1
```

看到 `Build environment looks usable.` 就可以构建。

## 一键构建 APK

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_apk.ps1
```

如果想顺便跑测试：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_apk.ps1 -RunTests
```

如果环境放在自定义路径：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_apk.ps1 -DevEnv "E:\ipad_build\dev_env"
```

## 把当前机器环境打成可复制包

在这台机器上运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\package_portable_env.ps1
```

默认会生成：

```text
portable_build_env\
  dev_env\
    android-sdk\
    flutter\
    jdk-17.0.13+11\
  README.md
```

如果想直接生成 zip：

```powershell
powershell -ExecutionPolicy Bypass -File tools\package_portable_env.ps1 -Zip
```

注意：这个包会很大，适合拷贝 U 盘或网盘，不适合提交进 Git。项目的 `.gitignore` 已经忽略 `dev_env/` 和构建缓存，避免把几 GB 的工具链误提交。

## 为什么不直接把 JDK / Android SDK / Flutter 提交进 Git

这些工具链合起来通常是几 GB，包含大量二进制、缓存和平台包。放进 Git 会让仓库极慢，也容易带来不同系统路径和许可问题。

更稳的做法是：

- Git 里保存源码、脚本、环境说明。
- 本机用 `tools\package_portable_env.ps1` 生成可复制环境包。
- 新电脑把 `dev_env` 放到项目旁边，运行 `tools\build_apk.ps1`。
