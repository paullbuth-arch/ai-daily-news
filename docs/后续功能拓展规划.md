1. **数据安全**：本地 JSON 存储，换手机/丢手机=全没（最优先解决）

4. **单设备**：只能一台手机用，平板/换机无法同步

## 近期功能路线（v1.4 - v1.6）

按**对实际生意的价值**排序，不是堆功能：

### v1.4：数据安全 + AI 配置用户化

#### 1. 数据导入/导出备份（必做）

**价值**：换手机前导出，新手机导入，数据不丢。成本几乎为零。

**方案**：
- 「我的」页加「备份/恢复」入口
- 导出：把 `ipad_boss_data.json` + 图片目录打包成 zip，通过系统分享（微信发自己/存网盘/存云端）
- 导入：从文件选择 zip，解压恢复数据
- 可选：定期提醒备份（比如每 7 天没备份过就弹一次提示）

**改动量**：小。主要在 Storage 层加 export/import 方法 + MePage 加两个按钮。

#### 2. AI 配置用户化（必做）

**价值**：token 不再硬编码，换模型/换服务商不用改代码。

**方案**：
- `Storage.settings` 新增 `aiConfig` 字段：`{baseUrl, apiKey, model}`
- 新增「AI 配置页」（设置页入口），用户可填：
  - **协议 URL**：如 `https://api.deepseek.com/anthropic`（当前默认）
  - **API Token**：如 `sk-xxxx`（当前硬编码的那个改为默认值）
  - **模型名**：如 `deepseek-v4-flash`（当前默认）
- `AiService` 从 Storage 读取配置，不再用 `static const`
- 保留默认值（向后兼容），首次打开自动填入当前的 DeepSeek 配置
- 支持测试连接（点「测试」按钮发一个简单请求验证配置是否可用）

**改动文件**：
- `lib/ai_service.dart`：`_baseUrl/_apiKey/_model` 从 const 改为从 Storage 读取
- `lib/storage.dart`：`getAiConfig()` / `saveAiConfig()`
- `lib/main.dart`：新增 `AiConfigPage`，SettingsPage 加入口
- `lib/models.dart`：可选新增 `AiConfig` 类

**兼容性**：旧数据无 aiConfig 时，用默认值（当前硬编码的 DeepSeek 配置），无缝升级。

#### 3. 采购决策模块（你文档里提了，还没做）

**价值**：拿货时不再凭感觉，数据告诉你该不该收。

**方案**：
- 新增「采购决策页」，输入：型号 + 成本 + 数量
- 输出：
  - 该型号历史销量、平均利润、平均周转天数、压货率
  - 供应商历史表现（哪个渠道来的质量好）
  - AI 综合判断：「建议收 / 谨慎 / 不建议」，附理由
- 数据源：复用已有的 `getTurnoverByModel`、`getSupplierStats`、`getProfitByModel`

**改动量**：中。主要是新页面 + AI prompt。

### v1.5：多设备同步 + 售后闭环

#### 4. WebDAV 云同步（推荐）

**价值**：多设备自动同步，换手机无缝衔接，数据不怕丢。

**方案**：
- 设置页加「云同步」配置：填坚果云 WebDAV 地址 + 账号密码
- 每次数据变更后，增量上传 JSON 到坚果云
- 打开 app 时自动拉取最新数据
- 坚果云免费版每月 1GB 上传流量，数据文件才几 KB，完全够用

**改动量**：中。需要加 WebDAV 客户端（可用纯 Dart 实现 HTTP PUT/GET，零第三方依赖），处理冲突（最后写入胜 + 时间戳）。

#### 5. 售后追踪闭环

**价值**：控制采购风险，识别高质量供应商。

**方案**：
- 售后录入时增加「售后原因」分类：质量问题 / 买家反悔 / 描述不符 / 物流损坏
- 经营分析页增加「售后率统计」：按型号、按供应商
- 高售后率的供应商自动标红预警
- 售后费用已自动扣利润（v1.3.0 已实现），这里补的是原因分析

**改动量**：小。Order 加 `afterSaleReason` 字段，售后录入 dialog 加选择，AnalyticsPage 加统计。

### v1.6：效率优化

#### 6. 闲鱼效率优化

- **复用历史描述**：同型号二次上架时，一键复用上次的 AI 描述 + 微调
- **批量上架队列**：选多台设备，逐个生成封面图+描述，连续跳闲鱼发布
- **售价微调**：详情页直接改售价（不用进滞销页）

#### 7. 首页信息密度优化

- 今日GMV卡片加「环比昨日」百分比
- 快捷操作支持长按直达（长按「扫码」直接拍照，不用进页面选）

## AI 配置用户化（重要）

这是 v1.4 的重点，单独展开说明。

### 现状（v1.3.0）

```dart
// lib/ai_service.dart 硬编码
static const String _baseUrl = 'https://api.deepseek.com/anthropic';
static const String _apiKey = 'sk-b176b9545b78480d9fdc4a851644df45';
static const String _model = 'deepseek-v4-flash';
```

问题：换 token / 换模型 / 换服务商（如改用 OpenAI、通义千问）都要改代码重新编译。

### 目标设计

```
设置 → AI 配置
  ├── 协议 URL:  [https://api.deepseek.com/anthropic]
  ├── API Token: [sk-xxxx                        ]
  ├── 模型名:    [deepseek-v4-flash              ]
  ├── [测试连接]  ← 发一个简单请求验证
  └── [保存]
```

### 实现要点

1. **存储**：`Storage.settings['aiConfig'] = {baseUrl, apiKey, model}`，JSON 持久化
2. **读取**：`AiService.chat()` 每次从 `gStorage.getSettings()['aiConfig']` 读取，取不到用默认值
3. **默认值**：当前的 DeepSeek 配置作为兜底（向后兼容旧数据）
4. **测试连接**：点「测试」发一个 `{"messages":[{"role":"user","content":"hi"}],"max_tokens":10}` 的请求，返回 200 即成功
5. **多协议兼容**：当前只支持 Anthropic Messages API 格式。如果用户填的是 OpenAI 兼容 URL，需要根据 URL 自动判断协议格式（或加一个「协议类型」下拉选择）

### 协议适配说明

不同 AI 服务商的 API 格式不同：

| 服务商 | URL 格式 | 请求格式 |
|---|---|---|
| DeepSeek (Anthropic兼容) | `https://api.deepseek.com/anthropic` | Anthropic Messages |
| DeepSeek (OpenAI兼容) | `https://api.deepseek.com` | OpenAI Chat Completions |
| OpenAI | `https://api.openai.com/v1` | OpenAI Chat Completions |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI 兼容 |

**建议**：v1.4 先只支持 Anthropic 格式（当前已实现），加一个「协议类型」选项预留扩展。后续如有需要再加 OpenAI 格式适配。

## 商业化可能性评估

> 用户已明确表示**暂不考虑商业化，仅自用**。以下仅作记录，供未来参考。

### 三个台阶

| 台阶 | 形态 | 收入模式 | 关键动作 |
|---|---|---|---|
| **台阶1：自用**（当前） | 一个人用 | 省成本 | 把数据安全/AI配置做了 |
| **台阶2：小范围收费** | 卖给同行/徒弟 | 买断制 99-299元 | 加账号体系+数据隔离+隐私协议 |
| **台阶3：行业SaaS** | 华强北商家都用 | 订阅制 39/月 | 多端+云后端+开放平台对接 |

### 走台阶2的前提

1. 数据迁移到云端（WebDAV 不够，要上 Supabase 之类的 BaaS）
2. 多用户数据隔离
3. AI token 用户化（v1.4 已规划，自用也要做）
4. 隐私合规（用户数据存哪、怎么用）
5. 去掉硬编码 token（否则 API 费用会被薅爆）

### 市场判断

- 二手数码是千亿级市场，目前**没有好用的垂直 SaaS**，大多是 Excel + 微信群，是真空地带
- 华强北一栋楼就好几千家商家，潜在用户体量够
- 但垂直 SaaS 的获客成本高、商家付费意愿待验证
- **建议**：先把自用版打磨好，拿给两三个同行朋友试用，看他们愿不愿意付钱，比任何市场调研都准

### 如果将来要做，技术上的准备

当前架构是自用友好型，商用需要补的"骨头"：
- 账号体系（登录/注册）
- 云端数据存储（Supabase / Firebase）
- 多用户数据隔离
- 隐私协议 / 用户协议
- 应用商店上架合规

好消息是核心业务逻辑（库存/订单/利润/经营分析/AI）已经跑通且测试覆盖，这些"肉"不用推倒重来，补"骨头"即可。

- **v1.4**：数据备份 + AI配置用户化 + 采购决策（预计 1 个版本周期）
