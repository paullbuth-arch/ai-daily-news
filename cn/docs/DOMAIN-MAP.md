## 0. 判定规则（先读这一节）

### 0.1 证据只有两类

| 类别 | 含义 | 能不能核对 |
|---|---|---|
| **D · 真实对话 / 真机 dump** | 从真机上原样抄下来的消息文本与节点文本 | 能，文件就在本机 |
| **P · 平台规则 / 平台呈现** | 平台自己写出来的规则文字，或平台对无障碍服务开放的语义 | 能，同上 |

**提案和自述不算证据。** 下面两份只进「参考」列，不参与任何处置判定：

- **S1** = `_archive/xianyu-seller-spec/seller-assistant-spec.html`（店主侧改造提案）
- **S2** = `padtest/ipad_boss_app/**`（店主自述的发布文案域 / 选品域文档）

### 0.2 处置只有五种

| 处置 | 含义 |
|---|---|
| **保留** | 该维度在闲鱼场景有证据支持，措辞也不用改 |
| **改写** | 维度留下，但措辞 / 选项 / 判据必须重写。重写成什么若证据不足，同格另注「待店主确认」 |
| **删除** | 该维度在闲鱼场景结构性不存在，且证据能证明 |
| **新增** | 恋爱版没有、闲鱼有证据支持的维度 |
| **待店主确认** | 证据不足。**本文档不填** |

### 0.3 三条硬性纪律

1. **不发明**意图枚举 / 风险枚举 / 话术库 / 阈值。spec 里出现过的具体枚举与阈值，本文档一律不采纳，只在第 5 节列出待裁定。
2. 处置 = 改写的行，只写「必须改」，不写「改成什么」——除非证据直接给出。
3. 本文档不写代码、不改 `cn/CLAUDE.md`。

### 0.4 路径约定

## 6. 本文档的自验缺口

1. **样本量极小**：闲鱼侧真实对话只有 **9 条消息**（D1.1 三条 + D1.2 一条 + D2.1–D2.6 五条，其中两条与 D1 重复），且只有 **一个会话**。任何「样本内没有」都只是「这个样本里没有」，不等于「闲鱼没有」。第 4 节的 A 类问题基本都因此需要店主拍板。
2. **D2.2 的说话方无法确定**：引用回复把「正文 + 昵称 + 被引原文」粘在一个 `content-desc` 里（`XianyuRules.kt:22-33`），被引原文是谁说的、什么时候说的，dump 里没有信息。所以「买家索要购买记录」这个判断带不确定性。
3. **P1 是唯一一条平台规则文字**，且它是**反诈提示**，不是处罚条款。本文档没有、也无法从本机证明闲鱼的处罚尺度（封号 / 限权 / 扣分）。要写进产品，需要店主提供规则中心的可核对来源。
4. **未覆盖的消息类型**：语音、视频、订单卡片、红包、转账、系统提示（`README.md:73` 已记）。这些形态里可能出现新的意图维度，现在一条证据都没有。
5. **未验证「买家是否真的会砍价」**：D2.4 是一条**卖家侧草稿测试数据**还是**真实买家消息**，测试注释只说是「从真机 dump 原样抄下来」，没说哪一侧。若它是买家发的，则「议价 + 运费」有证据；若不是，则没有。→ 建议店主核对。
6. 本文档没有跑任何构建 / 测试，所有代码行号来自当前工作区文件（含未提交改动），改动后行号会漂移。
