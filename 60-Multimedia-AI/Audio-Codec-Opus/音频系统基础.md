# 音频系统基础

**一句话结论（20% 核心）**：嵌入式音频系统 = 麦克风采集 → 音频接口（PDM/I2S）传输 → DSP 处理 → 编解码压缩 → 输出/传输。整条链路的每个节点都有**采样率、位深、时钟**三个约束，理解这三个参数就能看懂任何音频问题。

---

## 第一层：核心认知

### 1.1 数字音频三要素

**一句话解释**：声音是连续的模拟波形，要数字化必须按固定频率"快照"（采样），每张快照的精度由位深决定，通道数决定同时录几个方向的声音。

#### 费曼类比

把数字音频想象成**拍电影**：

| 电影 | 音频 | 含义 |
|------|------|------|
| 帧率 (24fps) | **采样率** (Sample Rate) | 每秒"拍"多少次 |
| 分辨率 (1080p) | **位深** (Bit Depth) | 每次"拍"多精细 |
| 单机位/多机位 | **通道数** (Channels) | 同时录几个方向 |

```
模拟声波 (连续):  ∿∿∿∿∿∿∿
                      ↓ 采样 (每秒 16000 次)
数字音频 (离散):  [1234] [1256] [1198] [1302] ...
                  每个数字是一个 PCM 采样值 (16-bit)
```

| 参数 | 常见取值 | 影响 |
|------|----------|------|
| **采样率** | 8k / 16k / 44.1k / 48k Hz | 越高→频率范围越宽 (奈奎斯特定理：采样率 ≥ 2× 最高频率) |
| **位深** | 16bit / 24bit / 32bit | 越高→动态范围越大 (16bit = 96dB, 24bit = 144dB) |
| **通道数** | 单声道 / 立体声 / 4ch 阵列 | 越多→空间信息越丰富 |

#### 带宽速算

```
带宽 = 采样率 × 位深 × 通道数

例：16kHz × 16bit × 1ch = 256 kbps (未压缩)
例：48kHz × 24bit × 2ch = 2.3 Mbps (未压缩 CD 音质)
```

> **英文术语**：Sample Rate（采样率）、Bit Depth（位深）、Channel（通道）、PCM（Pulse Code Modulation，脉冲编码调制）。

### 1.2 PDM vs I2S：两种音频接口

**一句话解释**：PDM 是麦克风直接输出的"原始"数字信号 (1-bit, 高频)，I2S 是芯片之间传输 PCM 数据的"标准"接口 (多 bit, 低频)。

| 维度 | [[PDM 麦克风\|PDM]] | [[I2S 协议\|I2S]] |
|------|---------|---------|
| **信号线** | 2 根 (CLK + DATA) | 3 根 (BCLK + LRCK + DATA) |
| **数据格式** | 1-bit 密度调制 | 16/24-bit PCM |
| **需要转换** | 是 (Decimation Filter → PCM) | 否 (直接可用) |
| **适用场景** | 麦克风 → 芯片 | 芯片 → 芯片 / 芯片 → 功放 |
| **reGlasses 用在哪** | SDM0103B ×4 (采集) | MAX98357A (播放) + V881 (交换) |

```
音频采集链:
  声波 → PDM 麦克风 → [PDM 接口] → Decimation → PCM → [I2S] → DSP / 传输

音频播放链:
  数据源 → PCM → [I2S] → 功放 → 扬声器
```

详见 [[I2S 协议]]、[[PDM 麦克风]]、[[I2S 时钟树]]。

### 1.3 音频延迟：从嘴到耳

**一句话解释**：声音从麦克风进来到播放/传输出来的总时间，由链路上每个环节的延迟累加而成。

```
麦克风采集 → PDM→PCM 转换 → DMA 搬运 → DSP 处理 → 编码 → 传输 → 解码 → 播放
  ~1ms         ~2ms          ~1ms       ~5-20ms    ~20ms  变化大  ~20ms  ~1ms
```

| 环节 | 延迟来源 | 典型值 |
|------|----------|--------|
| 采样缓冲 | 凑够一帧再处理 | 帧长 / 采样率 (20ms@16kHz/320 采样) |
| DMA/中断 | 搬运 + 调度 | 0.1-1ms |
| DSP 算法 | AEC/降噪/AGC 计算 | 1-10ms |
| 编解码器 | Opus/AAC 编码 | 5-40ms (取决于帧长和复杂度) |
| 蓝牙传输 | 空中 + 协议栈 | 20-200ms (BLE GATT) 或 20-40ms (HFP SCO) |

**关键认知**：
- **通话场景**要求总延迟 < 150ms，所以用 HFP/SCO (经典蓝牙同步链路)
- **录音场景**延迟不敏感，可以用 BLE GATT + Opus 压缩
- **AEC (回声消除)** 需要精确的时间对齐，延迟抖动会导致 AEC 失效

### 1.4 如果只记得一件事

> 数字音频 = 采样率 × 位深 × 通道数。PDM 是麦的原始输出 (1-bit)，I2S 是芯片间的标准 PCM 接口。延迟是链路上每个环节累加的，通话场景对延迟最敏感。

## 第二层：实战理解

### 2.1 音频编解码器：为什么要压缩？

未压缩 PCM 带宽太大，传输和存储都需要压缩：

| 编解码器 | 类型 | 压缩比 | 延迟 | reGlasses 用途 |
|---------|------|--------|------|---------------|
| **Opus** | 通用 (语音+音乐) | 8-16× | 5-40ms | BLE 音频传输 |
| CVSD | 语音 (窄带) | 4× | <5ms | HFP 通话 (经典蓝牙) |
| mSBC | 语音 (宽带) | 4× | <10ms | HFP 宽带通话 |
| SBC | 音乐 | 3-5× | 10-30ms | A2DP 音乐 (必选) |
| AAC | 音乐 | 5-10× | 20-50ms | A2DP 音乐 (可选) |
| LC3 | 通用 (LE Audio) | 8-16× | 10-20ms | 未来 LE Audio |

```
PCM 16kHz/16bit/1ch = 256 kbps
        ↓ Opus 编码
Opus 帧 ~16-32 kbps (压缩 8-16 倍)
        ↓ BLE GATT Notify
手机收到 → Opus 解码 → PCM → 播放/ASR
```

### 2.2 AEC (回声消除)：为什么打电话时不会啸叫？

**问题**：扬声器播放对方的声音 → 被你的麦克风再次录入 → 对方听到自己的回声 → 无限循环 → 啸叫。

**解决**：AEC (Acoustic Echo Cancellation，声学回声消除) 用扬声器播放的信号作为参考，从麦克风信号中**减去**这部分回声。

```
                    ┌───────────────────────────┐
扬声器信号 ──────→ │   AEC 自适应滤波器          │
(参考信号)         │   估算回声路径              │
                    │   从麦克风信号中减去估算的回声 │
                    └───────────┬───────────────┘
                                ↓
麦克风信号 ──────────────────→ (-) → 干净信号 (只有你的声音)
(包含你的声音 + 回声)
```

**为什么 AEC 对延迟敏感？**
- AEC 需要精确对齐"扬声器信号"和"麦克风信号中的回声"
- 如果两者的时间差不稳定 (jitter)，AEC 滤波器无法收敛
- 这就是为什么通话场景用 HFP/SCO (保证时隙) 而不是 BLE GATT (尽力而为)

### 2.3 DSP 处理链：reGlasses 的音频处理

WQ7036AX 的 DCORE (HiFi5 DSP) 对采集到的音频做多步处理：

```
4ch PCM (16kHz/16bit)
    │
    ↓ AEC (Acoustic Echo Cancellation)
    │  如果扬声器在播放，消除回声
    │
    ↓ NR (Noise Reduction)
    │  去除环境噪声 (风扇、空调)
    │
    ↓ AGC (Automatic Gain Control)
    │  声音太小→放大，太大→压小
    │
    ↓ Beam Forming (波束成形)
    │  4 路麦组合，增强特定方向的声音
    │
    ↓ VAD (Voice Activity Detection)
    │  检测"有人在说话"，没说话时不发送
    │
    ↓ Opus 编码
    │
    ↓ BLE 发送 / 本地存储
```

在 SI 中搜索 `aud_sv_api.h` 可找到音频服务 API。

### 2.4 常见错误 / 易错点

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 采样率不匹配 | 声音变速 (变调) | 采集/播放/编码的采样率必须一致 |
| 大小端搞反 | 数据全是噪声 | 确认 CPU 字节序和协议字节序 |
| I2S 时钟不对 | 无声 / 爆音 | 确认 BCLK = 2 × 位深 × Fs |
| DMA 缓冲区太小 | 丢数据 / 断音 | 双缓冲 + 足够大的缓冲区 |
| AEC 参考信号延迟不对 | 回声消除失效 | 对齐扬声器和麦克风的时间戳 |

## 第三层：深入扩展

### 3.1 奈奎斯特采样定理

**定理**：采样率必须 ≥ 2 × 信号最高频率，否则会出现**混叠 (Aliasing)**——高频信号被错误地还原为低频信号。

| 场景 | 人耳范围 | 最低采样率 | 实际采用 |
|------|----------|-----------|----------|
| 电话语音 | 300-3400 Hz | 8 kHz | 8 kHz |
| 宽带语音 | 50-7000 Hz | 16 kHz | 16 kHz |
| CD 音质 | 20-20000 Hz | 44.1 kHz | 44.1 kHz |
| 专业音频 | 20-20000 Hz | 48 kHz | 48/96 kHz |

### 3.2 Opus 编码参数详解

Opus 是目前最适合嵌入式音频传输的编解码器：

| 参数 | 影响 | reGlasses 典型值 |
|------|------|-----------------|
| 采样率 | 输入 PCM 的采样率 | 16000 Hz |
| 帧长 | 每帧包含的采样时间 | 20ms (越小延迟越低，但压缩效率越低) |
| 码率 | 压缩后的目标比特率 | 16-32 kbps |
| 复杂度 | 编码器的计算复杂度 (0-10) | 0-2 (嵌入式 CPU 有限) |
| VBR | 可变码率 | 开启 (静音时码率自动降低) |

```
Opus 帧大小 = 码率 × 帧长 / 8
            = 24000 × 0.02 / 8
            = 60 bytes/帧
```

### 3.3 I2S 时钟设计

I2S 的三个时钟之间有严格的数学关系：

```
MCLK = N × Fs  (N 通常为 256 或 128)
BCLK = 2 × BitDepth × Fs
LRCK = Fs
```

详见 [[I2S 时钟树]]。

### 3.4 常见面试题

- **PDM 和 PCM 的区别？** PDM 是 1-bit 高采样率的密度调制信号，需要 Decimation Filter 转换成多 bit PCM。PCM 是标准的多 bit 采样值。
- **为什么蓝牙通话用 8k/16k，音乐用 44.1k/48k？** 通话只需要 300-3400Hz 的语音频率，8kHz 采样率够用。音乐需要覆盖人耳范围 20-20kHz，至少 44.1kHz。
- **I2S 主从模式下时钟由谁提供？** Master 提供 BCLK 和 LRCK，Slave 跟随。reGlasses 中 I2S #1 (V881↔WQ) 的 Master 是 V881，I2S #2 (WQ→功放) 的 Master 是 WQ7036AX。
- **什么是 AEC？为什么需要它？** AEC (Acoustic Echo Cancellation) 从麦克风信号中减去扬声器回声，防止通话时啸叫和回声。
- **Opus 编码的延迟来源是什么？** 主要来源是帧长 (20ms) + 编码计算 (5-20ms) + 解码 (5ms)。帧长越短延迟越低但压缩效率越低。
- **为什么 DMA 传输音频要用双缓冲？** DMA 和 CPU 不能同时操作同一块缓冲区。双缓冲让 DMA 写 A 时 CPU 处理 B，交替使用，永远不会冲突。
