# SPI 基础

**一句话结论（20% 核心）**：SPI 是嵌入式最快的通用总线——4 根线（时钟+数据出+数据入+片选），全双工，几十 MHz，比 UART 快几百倍，比 I2C 快几十倍。Flash、显示屏、WiFi 模块都在用。

---

## 第一层：核心认知（必须先看懂）

### 1.1 费曼类比：传送带+对讲机

SPI 就像一条**双向传送带**：
- **SCK（时钟）** = 传送带的节拍器，Master 控制节奏
- **MOSI（Master Out Slave In）** = Master 的嘴巴 → Slave 的耳朵
- **MISO（Master In Slave Out）** = Slave 的嘴巴 → Master 的耳朵
- **CS/SS（片选）** = 传送带的开关，拉低=选中这个设备，拉高=忽略

**关键特性**：SPI 是全双工的——MOSI 和 MISO 同时工作。Master 每发一个 bit，Slave 同时回一个 bit。就像两个人同时说话，各说各的。

```
Master                          Slave
  SCK ─────────────────────────→ SCK    (节拍器)
  MOSI ────────────────────────→ MOSI   (主→从 数据)
  MISO ←──────────────────────── MISO   (从→主 数据)
  CS  ─────────────────────────→ CS     (选中信号)
```

### 1.2 为什么 SPI 比 UART/I2C 快？

| 原因 | 解释 |
|------|------|
| **有独立的时钟线** | 不需要像 UART 那样靠波特率对齐，时钟可以跑到几十 MHz |
| **全双工** | 收发同时进行，不浪费带宽 |
| **没有地址开销** | 用 CS 硬件选设备，不需要像 I2C 那样先发地址 |
| **推挽输出** | 不像 I2C 用开漏+上拉电阻，SPI 主动驱动，边沿更陡 |

### 1.3 四种工作模式（CPOL + CPHA）

SPI 最让人困惑的地方：时钟极性和相位有 4 种组合。**但 90% 的设备用 Mode 0 或 Mode 3。**

| Mode | CPOL（空闲电平） | CPHA（采样边沿） | 常见设备 |
|------|-----------------|-----------------|----------|
| **0** | 0（低） | 上升沿采样 | 最常用，大多数 SPI Flash |
| 1 | 0（低） | 下降沿采样 | 少见 |
| 2 | 1（高） | 下降沿采样 | 少见 |
| **3** | 1（高） | 上升沿采样 | SD 卡、部分显示屏 |

**一句话记忆**：CPOL 决定空闲时 CLK 是高是低，CPHA 决定在第几个边沿采样。配错了设备不工作，改一下就行，不会烧坏。

### 1.5 如果只记得一件事

> SPI = 4 根线（SCK/MOSI/MISO/CS），全双工，Master 控时钟，CS 选设备。极快（几十 MHz），没有地址概念，靠 CS 硬件片选。90% 设备用 Mode 0。

## 第二层：实战理解

### 2.1 典型读写流程

```c
// 读 SPI Flash 的 JEDEC ID（几乎所有 SPI Flash 都支持这个命令）
// 命令: 0x9F，返回 3 字节的制造商+设备 ID

uint8_t tx_buf[4] = {0x9F, 0x00, 0x00, 0x00};  // 发命令+读 3 字节
uint8_t rx_buf[4] = {0};

// CS 拉低 → 传输 4 字节 → CS 拉高
gpio_set_level(CS_PIN, 0);
spi_transfer(SPI_PORT, tx_buf, rx_buf, 4);
gpio_set_level(CS_PIN, 1);

// rx_buf[1..3] = {manufacturer_id, memory_type, capacity}
printf("JEDEC ID: %02X %02X %02X\n", rx_buf[1], rx_buf[2], rx_buf[3]);
```

### 2.2 常见坑

| 问题 | 现象 | 根因 |
|------|------|------|
| Mode 配错 | 读出全是 0xFF 或乱码 | 采样边沿不对，换 Mode 试 |
| CS 忘拉低 | 设备不响应 | SPI 设备靠 CS 下降沿"唤醒" |
| 速率太高 | 数据偶尔出错 | 超过设备支持的最高频率，降低 SCK |
| 多设备 CS 冲突 | A 设备发出了 B 设备的数据 | 同时只拉低一个 CS |

### 2.3 在 reGlasses/WQ7036AX 项目中怎么用

reGlasses 当前硬件上 SPI 未使用（Flash 是内部总线，不通过 SPI 外设），但在类似项目中 SPI 的典型用途：

- **SPI Flash**：外挂固件存储（WQ7036AX 内部 Flash 不够时）
- **SPI 显示屏**：智能眼镜的微型 OLED（通过 SPI 发命令+像素数据）
- **SPI WiFi 模块**：ESP32 等通过 SPI 从机模式与主控通信

WQ7036AX 的 SPI 驱动在 `wqcore/driver/spi/` 下，API 模式与 UART/I2C 一致。

## 第三层：深入扩展

### 3.1 UART vs I2C vs SPI 最终对比

| | UART | I2C | SPI |
|---|---|---|---|
| 线数 | 2 | 2 | **4** |
| 速度 | 115k-4M bps | 100k-3.4M bps | **10-50M bps** |
| 全双工 | 是 | 否 | **是** |
| 多设备 | 否 | **是（地址）** | 是（CS） |
| 复杂度 | 最低 | 中 | 中 |
| 典型用途 | 调试/命令 | 传感器 | Flash/显示/高速 |

### 3.2 常见问题

- **SPI 为什么需要 4 根线？** 时钟+数据出+数据入+片选。全是独立信号，不需要地址解码，所以快。
- **Mode 0 和 Mode 3 的区别？** 空闲电平不同，Mode 0 空闲低，Mode 3 空闲高。采样边沿都是第一个边沿。
- **SPI 能挂多少个设备？** 理论上无限，每个设备一根 CS 线。实际受 GPIO 数量限制。
