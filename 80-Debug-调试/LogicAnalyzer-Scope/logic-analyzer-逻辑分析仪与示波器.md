# 逻辑分析仪与示波器

## 一句话结论

逻辑分析仪看数字信号（0/1 的电平变化），示波器看模拟信号（电压波形）。通信协议调试（UART/I2C/SPI）用逻辑分析仪，信号质量（时钟抖动、电源噪声）用示波器。

## 30秒先看懂

- 逻辑分析仪记录数字信号的电平变化，通过协议解码器自动解析 UART/I2C/SPI 等通信协议的内容。示波器显示完整的模拟电压波形，可以看到信号的上升沿/下降沿时间、过冲、振铃、噪声等模拟特性。嵌入式开发 80% 的通信问题用逻辑分析仪就能解决——采样率足够（通常是信号频率的 4 倍以上），接好地线，设置正确的触发条件。示波器在排查信号完整性问题时使用——时钟抖动、电源纹波、信号质量。在 reGlasses 项目中，WQ7036AX 和 V881 之间的 UART 通信问题用逻辑分析仪抓波形，I2C 通信问题（ELM2713 不响应）同样用逻辑分析仪解决。

## 学完以后应该能做什么

**第一遍看完后可以：**
- 区分逻辑分析仪和示波器的适用场景
- 用逻辑分析仪抓取并解码 UART/I2C/SPI 通信
- 正确连接探头和地线
- 设置合适的采样率和触发条件

**进阶后可以：**
- 用示波器测量信号质量（上升时间、过冲、抖动）
- 分析电源噪声和纹波
- 调试复杂的时序问题（多信号同步）
- 使用逻辑分析仪的触发条件捕获特定事件

## 术语先讲清楚

| 中文 | 英文 | 具体含义 |
|------|------|---------|
| 逻辑分析仪 | Logic Analyzer | 记录数字信号电平，解码通信协议的工具 |
| 示波器 | Oscilloscope | 显示模拟电压波形的测量仪器 |
| 采样率 | Sampling Rate | 每秒采集的样本数量，单位 samples/s |
| 触发条件 | Trigger | 捕获信号的条件（如上升沿、下降沿、特定电平） |
| 协议解码 | Protocol Decoding | 逻辑分析仪自动解析 UART/I2C/SPI 等协议 |
| 信号完整性 | Signal Integrity | 信号质量，包括上升时间、过冲、振铃、抖动 |
| 上升时间 | Rise Time | 信号从 10% 到 90% 电平的时间 |
| 过冲 | Overshoot | 信号超过目标电平的部分 |
| 振铃 | Ringing | 信号在跳变后振荡的现象 |
| 抖动 | Jitter | 时钟边沿的位置偏差 |

## 第一层：费曼心智模型

### 类比：录音笔 vs 摄像机

- **逻辑分析仪** = 录音笔：只记录声音有没有（0/1），不关心声音大小，但能记录很长时间
- **示波器** = 摄像机：记录完整的画面细节（波形），能看到信号质量，但记录时间短

**边界：**
- 逻辑分析仪不能看模拟信号质量——不知道电压是 3.3V 还是 2.8V
- 示波器通道数少（通常 2-4 通道），逻辑分析仪可以 8-34 通道
- 逻辑分析仪采样率不够时可能漏掉短脉冲

### 场景演练：I2C 通信问题排查

1. 传感器 ELM2713 不响应 I2C 命令
2. 逻辑分析仪探头接 SCL 和 SDA，GND 共地
3. 设置采样率 2MHz（≥ 4 倍 I2C 速率）
4. 触发条件设为 SDA 下降沿（Start 条件）
5. 运行程序，逻辑分析仪抓到波形
6. 解码结果：`[S] 0x72 + W [A] 0x10 [A] [S] 0x72 + R [N] [P]`
7. 发现从设备在 Read 阶段返回了 NACK
8. 检查传感器 datasheet，发现寄存器地址需要先写入再读取特定长度
9. 修复代码中的 I2C 读写长度

## 第二层：原理/时序/约束

### 逻辑分析仪和示波器对比

| 对比项 | 逻辑分析仪 | 示波器 |
|--------|----------|--------|
| 看什么 | 数字信号（0/1） | 模拟信号（电压波形） |
| 通道数 | 8-34 通道 | 1-4 通道 |
| 典型用途 | 解码 UART/I2C/SPI 协议 | 检查时钟抖动、电源纹波、信号完整性 |
| 价格 | 便宜（几十到几百元） | 贵（几千到几万元） |
| 采样率 | 100M-1G samples/s | 100M-5G samples/s |
| 存储深度 | 深（可记录长时间） | 浅（记录时间短） |

### 采样率选择

```
采样率 >= 信号频率 x 4

举例：
  UART 115200 baud → 信号频率 ~115kHz → 采样率 >= 460kHz
  I2C 400kHz      → 信号频率 ~400kHz → 采样率 >= 1.6MHz
  SPI 10MHz       → 信号频率 ~10MHz  → 采样率 >= 40MHz
```

### 逻辑分析仪解码 I2C

```
连接:
  CH0 → SCL
  CH1 → SDA
  GND → GND

解码结果:
  [S] 0x72 + W [A] 0x10 [A] 0x03 [A] [P]
   │     │   │   │    │   │    │   │   │
  Start 地址  ACK 寄存器 ACK 数据 ACK Stop
```

## 第三层：真实 SDK 代码

### 用 GPIO 辅助逻辑分析仪调试

```c
// 在关键代码位置翻转 GPIO，用逻辑分析仪抓取时序
#define DBG_GPIO_ON()   gpio_set_level(DEBUG_PIN, 1)
#define DBG_GPIO_OFF()  gpio_set_level(DEBUG_PIN, 0)

void uart_send_data(const uint8_t *data, size_t len) {
    DBG_GPIO_ON();  // 开始发送
    for (size_t i = 0; i < len; i++) {
        uart_putchar(data[i]);
    }
    DBG_GPIO_OFF();  // 发送结束
    // 用逻辑分析仪看 DEBUG_PIN 的高电平宽度 = 发送时间
}

void i2c_transaction_debug(void) {
    DBG_GPIO_ON();  // I2C 事务开始
    i2c_write(addr, reg, data);
    DBG_GPIO_OFF(); // I2C 事务结束
    // 逻辑分析仪同时抓 I2C 信号和 DEBUG_PIN
    // 可以精确看到 I2C 事务的每个步骤的耗时
}
```

### reGlasses 中的调试连接

WQ7036AX 和 V881 之间的 UART 通信问题调试方法：
- 逻辑分析仪探头夹在 TX/RX 线上
- 直接看波特率对不对（测量一个 bit 的宽度，倒数得波特率）
- 看数据内容对不对（解码后对比预期数据）
- 看是否有数据丢失或错位

## 第四层：正常/异常路径

### 正常路径

逻辑分析仪：连接探头 → 设置采样率 → 设置触发条件 → 开始捕获 → 触发 → 解码 → 分析

### 异常路径

| 异常场景 | 现象 | 原因 | 处理方式 |
|---------|------|------|---------|
| 采样率不够 | 解码结果不完整，漏掉 bit | 采样率 < 4 倍信号频率 | 提高采样率 |
| 地线没接 | 信号全是噪声 | 逻辑分析仪和被测设备电位差 | 接好 GND 线 |
| 触发条件设错 | 抓不到想要的波形 | 触发条件不对 | 确认触发信号的特征 |
| 探头负载太大 | 信号变形 | 探头电容影响了高速信号 | 使用低电容探头 |
| 存储深度不够 | 波形记录不全 | 存储深度不足以记录完整事件 | 降低采样率以延长记录时间 |

## 第五层：调试方法

### 逻辑分析仪调试技巧

```bash
# 测量 UART 波特率
# 1. 抓一个字节的波形（起始位 0 + 8 数据位 + 停止位 1）
# 2. 测量起始位到第一个数据位的宽度 = bit 时间
# 3. 1 / bit 时间 = 实际波特率
# 例如：bit 时间 = 8.68μs → 波特率 = 115200

# 测量 I2C 速率
# 测量 SCL 一个周期的宽度 = 时钟周期
# 1 / 时钟周期 = I2C 速率
```

### 示波器调试技巧

```bash
# 测量电源纹波
# 1. 探头设为 1x 衰减（不是 10x）
# 2. AC 耦合
# 3. 带宽限制 20MHz
# 4. 测量峰峰值（Vpp），一般要求 < 50mV

# 测量时钟抖动
# 1. 使用余辉模式（Persistence）
# 2. 看时钟边沿的叠加
# 3. 抖动大的话边沿会模糊
```

## 第六层：实战练习

### 练习 1：UART 解码（基础）

用逻辑分析仪抓取 UART 通信：
1. 连接逻辑分析仪到 UART 的 TX 和 GND
2. 设置采样率 2MHz，触发设为下降沿
3. 单片机发送 "Hello" 字符串
4. 逻辑分析仪解码，验证数据正确
5. 故意改错波特率，观察解码结果的变化

### 练习 2：I2C 时序分析（进阶）

用逻辑分析仪抓取 I2C 通信并分析：
1. 连接逻辑分析仪到 I2C 的 SCL、SDA 和 GND
2. 设置采样率 4MHz，触发设为 SDA 下降沿
3. 执行一次 I2C 读写操作
4. 解码并分析：Start 条件、地址、ACK/NACK、数据、Stop 条件
5. 测量 SCL 的实际频率，检查是否与配置一致

### 练习 3：信号质量分析（深入）

用示波器分析信号质量：
1. 测量 UART TX 信号的上升时间和下降时间
2. 观察是否存在过冲或振铃
3. 测量电源轨的纹波
4. 分析时钟抖动
5. 尝试改变上拉电阻值，观察信号质量的变化

## #flashcard

**Q: 逻辑分析仪和示波器的区别？**
A: 逻辑分析仪看数字信号（0/1），解码通信协议；示波器看模拟信号（电压波形），检查信号质量。

**Q: 逻辑分析仪的采样率至少要是信号频率的多少倍？**
A: 至少 4 倍，才能可靠地重建数字信号。

**Q: 为什么逻辑分析仪必须和被测设备共地？**
A: 不共地会导致电位差，信号全是噪声，无法正确测量。

**Q: 嵌入式开发 80% 的通信问题用什么工具解决？**
A: 逻辑分析仪。UART/I2C/SPI 协议解码全靠它。

**Q: 示波器主要用来排查什么问题？**
A: 信号完整性（上升时间、过冲、振铃、抖动、电源纹波）。
