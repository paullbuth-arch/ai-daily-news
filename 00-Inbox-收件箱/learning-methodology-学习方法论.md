# 学习方法论与二八定律

**一句话结论**：嵌入式协议学习不需要追求完全精通——用 20% 的核心知识可以覆盖 80% 的日常开发场景。核心知识包括：协议是什么、物理层、数据帧格式、初始化流程、常见 API 调用。

---

## 30 秒先看懂

- 嵌入式学习有五种公认有效的方法：分层递进法、项目驱动法、源码阅读法、对比学习法、可视化工具法。
- 二八定律告诉我们：每个协议花 20% 的时间学 20% 的核心知识，就能覆盖 80% 的开发场景。
- 学习优先级：WQ Protocol ≥ BLE GATT > STTP > I2S/PDM > I2C/GPIO。
- 80/20 高效学习路径约需 4-6 个月（每天 2-3 小时），完全精通需要 3-5 年。
- 对于 SDK 应用层开发者，80/20 路径性价比最高。

---

## 学完以后应该能做什么

**第一遍学完**：
- 能说出五种学习方法并选择适合自己的组合
- 能应用二八定律确定协议学习的优先级
- 能用一句话描述每个协议的核心用途

**进阶目标**：
- 能制定自己的学习计划，合理分配时间
- 能根据项目需求快速学习新协议
- 能判断什么时候该深入、什么时候该满足于 80/20

| 二八定律 | Pareto Principle (80/20 Rule) | 80% 的产出来自 20% 的投入，学习中指核心知识覆盖大部分场景 |
| 分层递进 | Layered Progression | 自底向上逐层学习，从物理层到应用层 |

## 第一层：费曼心智模型

### 类比：学开车 vs 学造车

| 学习路径 | 类比 | 嵌入式对应 |
|----------|------|-----------|
| 80/20 高效学习 | 学开车 | 会用 SDK API 开发应用、调试问题 |
| 完全精通 | 学造车 | 能写协议栈、造芯片驱动 |

**你需要什么？** 对于 reGlasses 项目，你的角色是应用层开发者——你不需要从零写蓝牙协议栈或音频编解码器，你只需要学会**调用 SDK 提供的 API** 来实现业务逻辑。这就是"学开车"，不是"学造车"。

### 五种学习方法

| 方法 | 一句话 | 在 reGlasses 中的应用 |
|------|--------|----------------------|
| **分层递进法** | 自底向上逐层理解，不跳跃 | PHY → STTP 帧 → GATT 传输 → WQ Protocol 命令 |
| **项目驱动法** | 协议不是学出来的，是调出来的 | 逻辑分析仪抓波形、nRF Connect 读写 GATT |
| **源码阅读法** | 从 SDK 已有实现入手 | `ota_transport_ble.c` 看 GATT Service 注册 |
| **对比学习法** | 相似协议放一起对比 | UART vs I2C, I2S vs PDM, BLE vs WiFi |
| **可视化工具** | 看图比看文字快 3 倍 | 逻辑分析仪 + GIF 动画 + nRF Sniffer |

### 边界

- 80/20 法则适用于**应用层开发**，不适用于需要写协议栈的场景。
- 五种方法不是互斥的，可以组合使用（如：分层递进 + 源码阅读是最常见的组合）。
- 学习优先级排序是基于 reGlasses 项目的实际需求，不同项目可能不同。

## 第二层：原理、时序与约束

### 二八定律在协议学习中的应用

每个协议的 **20% 核心知识**：

1. **协议是什么** — 一句话描述用途
2. **物理层/线数** — 几根线、什么电平
3. **数据帧格式** — 报文结构（头 + 载荷 + 校验）
4. **初始化流程** — 上电后怎么配置
5. **常见 API 调用** — SDK 中怎么用它

### 学习优先级（投入产出比排序）

| 优先级 | 协议 | 理由 |
|--------|------|------|
| 最高 | WQ-Audio-Protocol | 所有业务数据的封装格式 |
| 最高 | BLE GATT | 与手机通信的唯一通道 |
| 最高 | STTP 协议 | MCU↔V881 主干通信 |
| 中 | I2S / PDM | 音频进出管道 |
| 低 | I2C / GPIO | 外设管理，驱动已有 |

### 时间估算

| 方法 | 每天投入 | 总周期 | 效果 |
|------|----------|--------|------|
| 纯看文档 | 2h | 3-4 月 | 能看懂代码 |
| 文档 + 实验 | 2-3h | 4-6 月 | 能独立调试 |
| 项目实战 | 全天 | 2-3 月 | 快速迭代 |

### 完全精通 vs 80/20

| 对比项 | 完全精通 | 80/20 高效学习 |
|--------|---------|---------------|
| 时间 | 3-5 年 | 4-6 个月 |
| 每天投入 | 4-8h | 2-3h |
| 适合角色 | 协议栈开发者 | 应用层开发者 |
| 输出能力 | 能写协议栈 | 能独立开发调试 |
| 翻车概率 | 低 | 中（遇到底层问题需要求助） |

## 第三层：真实 SDK 代码

### 源码阅读法

从 SDK 已有实现入手，是最快的学习方式：

| 协议 | 文件 | 学什么 |
|------|------|--------|
| BLE GATT | `wq-adk/components/apps/acore/ota/src/ota_transport_ble.c` | GATT Service 注册、Characteristic 读写 |
| STTP 协议 | `wq-adk/examples/glass/acore/app/app_customer_ext_trans/app_uart_cmd.c` | 帧解析状态机、命令路由 |
| WQ Protocol | `wq-adk/components/wq_protocol/` | 帧结构定义、pack/unpack 函数 |
| 音频服务 | `wq-adk/components/audio_service/api/aud_sv_api.h` | 音频采集/播放 API |

### 对比学习法

| 对比组 | 关键差异 |
|--------|---------|
| UART vs I2C | UART 异步（需波特率匹配），I2C 同步（需时钟） |
| I2S vs PDM | I2S 多 bit 并行，用于播放；PDM 1-bit 串行，用于采集 |
| BLE vs WiFi | BLE 低功耗低带宽（~1Mbps），WiFi 高功耗高带宽（~100Mbps） |

## 第四层：常见学习障碍

| 问题 | 表现 | 建议 |
|------|------|------|
| 追求完美 | 想学完所有细节，进度极慢 | 用 80/20 法则，只学核心 20% |
| 只看不练 | 看完就忘，不会用 | 每学一个协议，必须动手写代码或抓波形 |
| 没有方向 | 不知道学什么，焦虑 | 按学习计划的优先级顺序来 |
| 缺乏反馈 | 不知道学得对不对 | 做验收 checklist，用 nRF Connect 等工具验证 |
| 贪多求快 | 同时学多个协议，混淆 | 一周只学一个协议，学透再继续 |

---

## 第五层：调试学习方法

- 如果发现学完就忘，说明没有实践——每学一个协议，必须动手操作（写代码、抓波形、用工具）。
- 如果发现进度太慢，检查是否在追求完美——用 80/20 法则，先学核心 20%。
- 如果发现概念混淆，用对比学习法——把相似协议放一起对比差异。
- 如果发现缺乏动力，用项目驱动法——找一个实际需求，边做边学。

## 第六层：实战练习

### 练习 1：应用 80/20 法则

选择 WQ-Audio-Protocol 协议，用 80/20 法则列出它的 20% 核心知识：
- 协议是什么（一句话）
- 物理层/传输方式
- 数据帧格式（头 + 载荷 + 校验）
- 初始化流程
- 常见 API 调用

### 练习 2：选择学习方法组合

根据你的学习风格，从五种学习方法中选择最适合你的 2-3 种组合，并说明：
- 为什么选择这些方法？
- 这些方法如何应用到 reGlasses 项目中？
- 你打算如何安排学习时间？

### 练习 3：制定学习计划

基于 80/20 法则，为以下场景制定一个 2 周的学习计划：
- 目标：学会在 WQ7036AX 上添加一个新的 BLE 命令
- 背景：你已经了解了基本架构

### 练习 4：阅读真实源代码

打开 `wq-adk/components/apps/acore/ota/src/ota_transport_ble.c`，用源码阅读法分析 BLE GATT Service 的注册流程。写出从 `ble_init` 到 Characteristic 注册的完整函数调用链。
