# 学习方法论与二八定律

## 是什么

嵌入式协议学习的策略指南：**不追求完全精通，而是用 20% 的核心知识覆盖 80% 的日常开发场景**。

## 五种公认有效的学习方式

### 1. 分层递进法（结构化思维）

自底向上逐层理解，不跳跃：

```
物理层 → 链路层 → 传输层 → 应用层
```

对本项目：PHY → STTP 帧 → GATT 传输 → WQ Protocol 命令

> 知乎 BLE 分层全解析系列采用"基础认知 → 机制详解 → 开发实战 → 进阶优化"四步递进。

### 2. 项目驱动法（Reddit 社区最推荐）

> "协议不是学出来的，是调出来的。"

- 逻辑分析仪抓波形，对照时序图
- nRF Connect 手机 APP 直接读写 GATT
- Wireshark + HCI log 抓蓝牙包

### 3. 源码阅读法

从 SDK 已有实现入手：
- `ota_transport_ble.c` → 已有完整 GATT Service 注册示例
- `sttp.c` → 已有完整帧解析状态机
- `wq_protocol.h` → 已有帧结构定义

### 4. 对比学习法

把相似协议放一起对比（UART vs I2C, I2S vs PDM, BLE vs WiFi），快速建立知识网络。

### 5. 可视化工具

逻辑分析仪 + GIF 动画 + nRF Sniffer，比纯文字理解快 3 倍。

## 二八定律在协议学习中的应用

每个协议的 **20% 核心知识**：

1. **协议是什么** — 一句话描述用途
2. **物理层 / 线数** — 几根线、什么电平
3. **数据帧格式** — 报文结构（头 + 载荷 + 校验）
4. **初始化流程** — 上电后怎么配置
5. **常见 API 调用** — SDK 中怎么用它
