# 计算机组成与 MCU 架构

**一句话结论（20% 核心）**：MCU（单片机）就是一颗把 CPU、内存、外设控制器全部塞进一个封装里的芯片。你写的每一行代码最终都是在操控这三样东西：CPU 执行指令，内存存数据，外设控制器和外面的世界交互。

---

## 第一层：核心认知（必须先看懂）

### 1.1 费曼类比：芯片就像一个小公司

把一颗 MCU 芯片想象成一个小公司：

| 芯片部件 | 类比 | 干什么 | WQ7036AX 里实际是什么 |
|---|---|---|---|
| **CPU** | 公司里的**员工** | 执行指令，做计算和判断 | RISC-V 核，240MHz |
| **Flash**（闪存） | **档案柜** | 永久存放程序代码，断电不丢 | ~4MB，存你的固件 |
| **SRAM**（静态内存） | **工作台** | 临时存放运行中的数据，断电清零 | ~1MB，存变量和栈 |
| **总线（Bus）** | **走廊** | 连接所有部件，数据在走廊上跑 | AHB/APB 总线 |
| **外设控制器** | **对外窗口** | 和外面的芯片/传感器通信 | UART/I2C/I2S/GPIO/PDM |
| **中断控制器** | **门铃系统** | 外设有事就按门铃通知 CPU | NVIC/PLIC |
| **时钟树** | **节拍器** | 给每个部件提供工作节奏 | 32MHz 晶振 → PLL 倍频 |

**关键理解**：CPU 是唯一的员工。它从 Flash（档案柜）取指令，在 SRAM（工作台）上处理数据，通过外设（窗口）和外界交互。工作台很小（~1MB），所以你不能像在 PC 上那样随便 malloc 大块内存。

### 1.2 芯片上电后发生了什么？（这个很重要）

芯片上电不是直接跳到你的 `main()` 函数。中间有一段"幕后工作"：

```
按下电源键
    │
    ▼
硬件复位：所有寄存器回到默认值
    │
    ▼
CPU 从 Flash 地址 0 读第一条指令（启动代码 startup.S）
    │
    ├── ① 初始化栈指针（SP）── 没有栈，C 函数无法调用
    ├── ② 把 .data 段从 Flash 拷到 SRAM（已初始化的全局变量）
    ├── ③ 把 .bss 段清零（未初始化的全局变量）
    ├── ④ 配置中断向量表（告诉 CPU 中断来了往哪跳）
    │
    ▼
system_init()：初始化时钟、电源、引脚
    │
    ▼
main()：终于到你的代码了！
```

**为什么这事重要？** 如果你的全局变量初值不对、或者程序一启动就崩溃，根因大概率在启动流程里。WQ7036AX 的启动代码在 `wqcore/components/startup/boot/` 下。

### 1.3 寄存器：操控硬件的唯一方式

**一句话**：寄存器就是外设的"控制面板"。GPIO 控制器有一排寄存器，写 1 让引脚输出高电平，写 0 输出低电平。这些寄存器被映射到特定的内存地址，你用 C 指针去读写它们。

**费曼类比**：把寄存器想象成配电箱里的一排空气开关。每个开关控制一个电路。地址就是开关的编号，写 1 就是合上开关，写 0 就是拉下开关。

```c
// 这不是"普通的内存读写"，而是"摸到了 GPIO 控制器的开关面板"
volatile uint32_t *gpio_out = (uint32_t *)0x40000000;
*gpio_out = 0x01;  // 合上第 0 号开关 → LED 亮
```

`volatile` 的作用：告诉编译器"每次都要真的去拨开关，不许偷懒用缓存值"。

### 1.4 内存映射：为什么指针能操控硬件？

WQ7036AX 把 Flash、SRAM、外设寄存器全部放在同一个地址空间里。CPU 访问地址 0x20000000 是读写 SRAM，访问地址 0x40000000 是操控 UART 控制器——用的是同一条指令，区别只在于地址指向哪里。

```
地址空间（简化示意）：
0x00000000 ┌────────────┐
           │   Flash    │  存代码（取指令）
0x00400000 ├────────────┤
           │   ...      │
0x20000000 ├────────────┤
           │   SRAM     │  存变量、栈、堆
0x20100000 ├────────────┤
           │   ...      │
0x40000000 ├────────────┤
           │   UART     │  串口控制器寄存器
0x40010000 ├────────────┤
           │   I2C      │  I2C 控制器寄存器
0x40020000 ├────────────┤
           │   GPIO     │  GPIO 控制器寄存器
           └────────────┘
```

### 1.5 如果只记得一件事

> MCU = CPU（员工） + Flash（档案柜） + SRAM（工作台） + 外设（窗口）。CPU 从 Flash 取指令，在 SRAM 上处理数据，通过读写特定地址的寄存器来操控外设。工作台很小，写代码要省着用内存。

## 第二层：实战理解

### 2.1 WQ7036AX 为什么有三个核？

WQ7036AX 是一颗**三核异构 SoC**，三个核各干各的：

| 核 | 架构 | 干什么 | 类比 |
|---|---|---|---|
| **ACORE** | RISC-V | 跑 FreeRTOS，应用逻辑、外设驱动、BLE 主机栈 | 公司 CEO —— 做决策、管外设、协调全局 |
| **BCORE** | RISC-V | 蓝牙底层射频协议栈（BT Controller） | 专职翻译 —— 只负责和手机蓝牙通信 |
| **DCORE** | Xtensa HiFi5 | 音频 DSP（降噪、AEC、Opus 编码、KWS 唤醒词） | 专业调音师 —— 只做音频算法 |

**为什么不分三个核？** 因为：
- 音频 DSP 算法需要大量乘加运算，通用 CPU 做太慢（HiFi5 比 RISC-V 快 10-50 倍）
- 蓝牙协议栈对实时性要求极高（微秒级），不能被应用层任务打断
- 不需要音频时，DCORE 可以完全断电省电

**核间怎么通信？** 通过共享内存 + 软中断。ACORE 往共享内存写数据，发一个软中断通知 BCORE/DCORE 来读。详见 [[多核通信与 IPC]]。

### 2.2 RISC-V 是什么？和 ARM 有什么区别？

**一句话**：RISC-V 和 ARM 都是 CPU 的"语言"（指令集架构）。区别是 ARM 要付费授权，RISC-V 开源免费。

| 对比维度 | ARM Cortex-M4（STM32 用的） | RISC-V（WQ7036AX 用的） |
|---|---|---|
| 指令集 | ARM Thumb-2 | RV32IMAC |
| 寄存器数量 | 16 个通用寄存器 | 32 个通用寄存器 |
| 授权费 | 需向 ARM 付费 | 免费开源 |
| 生态成熟度 | 非常成熟，教程多 | 快速增长中 |
| 对写 C 代码的影响 | 几乎感觉不到差异 | 几乎感觉不到差异 |

**对初学者的影响**：写 C 代码时完全感觉不到区别。只有看汇编、写启动代码、做极致优化时才需要关心。

### 2.3 时钟树：芯片的"心跳"从哪来？

```
32MHz 外部晶振（X4）
    │
    ├──→ PLL 倍频到 240MHz → CPU 时钟（ACORE/BCORE）
    ├──→ 分频到 48MHz → UART/USB 时钟
    ├──→ 分频到 24MHz → I2C 时钟
    ├──→ 音频 PLL → 12.288MHz → I2S/PDM 时钟
    └──→ 32kHz 内部振荡器 → 休眠时维持定时器
```

**为什么需要这么多不同的频率？**
- CPU 要快（240MHz），但快意味着费电
- UART 波特率 115200 需要从特定频率分频得到
- I2S 音频需要精确的采样率（16kHz × 256 × 2ch = 8.192MHz 的 BCLK）
- 休眠时只需 32kHz 维持一个定时器，功耗极低

**常见坑**：UART 通信乱码，80% 的情况是时钟源配错了，导致波特率不准。

### 2.4 实际代码：WQ7036AX 的外设是怎么初始化的

在 SDK 中，外设的使用遵循统一模式：

```c
// 1. 使能时钟（让外设模块"通电"）
apb_clk_enable(CLK_UART1);

// 2. 配置引脚复用（把 GPIO 引脚分配给 UART 功能）
gpio_set_mux(GPIO50, GPIO_MUX_UART1_TX);
gpio_set_mux(GPIO51, GPIO_MUX_UART1_RX);

// 3. 配置外设参数（波特率、数据位、停止位等）
uart_config_t cfg = {
    .baud_rate = 115200,
    .data_bits = 8,
    .stop_bits = 1,
    .parity    = UART_PARITY_NONE,
};
uart_init(UART_PORT_1, &cfg);

// 4. 注册中断回调（外设有事时通知你）
uart_register_rx_callback(UART_PORT_1, my_rx_handler);
```

这个模式适用于所有外设（UART、I2C、I2S、GPIO 中断），只是配置参数不同。

## 第三层：深入扩展

### 3.1 流水线：CPU 为什么这么快？

现代 CPU 不是"取一条指令→执行完→取下一条"这样串行的，而是像工厂流水线一样重叠执行：

```
时钟周期:   1      2      3      4      5
指令1:   [取指] [译码] [执行] [访存] [写回]
指令2:          [取指] [译码] [执行] [访存] [写回]
指令3:                 [取指] [译码] [执行] [访存]
```

理想情况下每个周期完成一条指令。但遇到 if/else 分支跳转时，流水线要清空重来，浪费几个周期。

### 3.2 哈佛架构：指令和数据分开走

| 架构 | 指令和数据 | 能同时取指令和取数据？ | 典型代表 |
|---|---|---|---|
| 冯诺依曼 | 走同一总线 | 不能 | 通用 PC |
| 哈佛 | 分开两套总线 | 能 | ARM Cortex-M、RISC-V |

WQ7036AX 的三个核都是哈佛架构——可以同时取指令和读写数据，效率更高。

### 3.3 为什么 Xtensa HiFi5 做音频这么快？

HiFi5 是专门为音频 DSP 优化的处理器：
- **SIMD**（单指令多数据）：一条指令同时处理 4-8 个音频采样点
- **硬件 MAC**（乘累加器）：音频算法 90% 是乘加运算，一个周期完成
- **零开销循环**：for 循环不需要额外指令来计数和跳转

同样的降噪算法，HiFi5 比 RISC-V 快 10-50 倍，功耗反而更低。

### 3.4 常见面试题

- **MCU 和 SoC 的区别？** MCU 偏控制，资源少，跑 RTOS/裸机；SoC 偏计算，资源多，能跑 Linux。
- **Flash 和 SRAM 的区别？** Flash 慢、容量大、断电不丢、擦写次数有限（~10 万次）；SRAM 快、容量小、断电丢数据、无限次读写。
- **为什么嵌入式要省内存？** 芯片 SRAM 只有几百 KB 到几 MB，没有虚拟内存，malloc 碎片化后可能分配失败。
- **什么是 MMIO？** Memory-Mapped IO，把外设寄存器映射到地址空间，用 C 指针直接访问。
- **volatile 能替代锁吗？** 不能。volatile 只保证每次都从内存读，不保证读-改-写的原子性。

### 3.5 核心术语表

| 英文 | 中文 | 一句话 |
|---|---|---|
| MCU | 单片机 | CPU+内存+外设封在一起的芯片 |
| SoC | 片上系统 | 比 MCU 复杂，能跑 Linux |
| ISA | 指令集架构 | CPU 的"语言"，定义它认识哪些指令 |
| RISC-V | 第五代精简指令集 | 开源免费的指令集，WQ7036AX 的 ACORE/BCORE 用它 |
| Xtensa HiFi5 | Cadence 音频 DSP | WQ7036AX 的 DCORE 用它做音频处理 |
| MMIO | 内存映射 IO | 把外设寄存器映射到内存地址来访问 |
| PLL | 锁相环 | 把晶振频率倍频/分频得到需要的时钟 |
| NVIC | 嵌套向量中断控制器 | ARM 的中断管理器 |
| PLIC | 平台级中断控制器 | RISC-V 的中断管理器 |
| HardFault | 硬件错误异常 | 程序崩溃的常见原因（访问非法地址等） |
