# 低功耗设计

**一句话结论（20% 核心）**：低功耗设计的核心思想是"能关则关、能慢则慢、能睡则睡"——让 MCU 在不工作的时候进入低功耗模式，只在需要时被唤醒。功耗 = 动态功耗（跑的时候耗电） + 静态功耗（睡着也耗电），两者都要优化。

---

## 第一层：核心认知

### 1.1 费曼类比：省电生活

低功耗就像日常省电：

| 省电行为 | MCU 低功耗策略 |
|---|---|
| 不用的电器拔掉插头 | **关闭不用外设的时钟（Clock Gating）** |
| 夏天空调开 26 度不用 16 度 | **降低 CPU 主频（DVFS）** |
| 人不在家就关灯 | **进入睡眠模式（Sleep / Deep Sleep）** |
| 闹钟响了再起床 | **配置唤醒源（Wake-up Source）** |

### 1.2 功耗的两个组成部分

| 类型 | 来源 | 优化方法 |
|---|---|---|
| **动态功耗** | CPU 运行、总线传输、外设工作时 | 降频、关外设、减少运算 |
| **静态功耗** | 晶体管漏电，即使不工作也耗电 | 进入深度睡眠、关闭电源域 |

**动态功耗公式**：P = C × V² × f
- C = 负载电容
- V = 供电电压
- f = 时钟频率

**结论**：**降电压比降频率更有效**（因为功耗与电压的平方成正比）。

### 1.3 常见低功耗模式

| 模式 | 功耗 | 唤醒速度 | 保留内容 | 唤醒源 |
|---|---|---|---|---|
| **运行（Run）** | 最高 | 无 | 全部 | — |
| **睡眠（Sleep）** | 较低（mA 级） | 快（μs） | CPU 状态、RAM | 任何中断 |
| **深度睡眠（Deep Sleep）** | 很低（μA 级） | 较慢（ms） | RAM | 特定中断（RTC/GPIO） |
| **待机（Standby）** | 最低（nA 级） | 最慢（等同于上电） | 部分寄存器/RTC | RTC/GPIO |

### 1.4 最小代码示例

```c
// ARM Cortex-M：进入睡眠模式
// WFI = Wait For Interrupt，CPU 停止执行直到中断唤醒
__WFI();

// 带深度睡眠的示例
void enter_deep_sleep(void) {
    // 1. 配置唤醒源（如 RTC 定时器 5 秒后唤醒）
    rtc_set_alarm(5000);  // 5 秒后
    rtc_enable_irq();

    // 2. 关闭不需要的外设时钟
    clk_disable(CLK_UART1);
    clk_disable(CLK_SPI1);

    // 3. 进入深度睡眠
    power_enter_deep_sleep();
    // --- CPU 停在这里 ---
    // --- 5 秒后被 RTC 唤醒，从这里继续执行 ---
}
```

### 1.5 如果只记得一件事

> 低功耗三板斧：关时钟（不用就关）、降频率（够用就慢）、进睡眠（没事就睡）。唤醒源决定了什么时候醒。

## 第二层：实战理解

### 2.1 时钟门控（Clock Gating）

每个外设都有一个时钟使能位。关闭时钟后，外设停止工作，功耗显著降低。

```c
// 初始化时只开需要的外设
void system_init(void) {
    clk_enable(CLK_GPIO);   // GPIO 必须开
    clk_enable(CLK_UART1);  // 调试串口
    // clk_enable(CLK_SPI1); // SPI 暂时不用，不开
    // clk_enable(CLK_I2C1); // I2C 暂时不用，不开
}

// 使用某个外设时才开时钟
void use_sensor(void) {
    clk_enable(CLK_I2C1);     // 用时开
    i2c_read(sensor_addr);
    clk_disable(CLK_I2C1);    // 用完关
}
```

### 2.2 动态电压频率调整（DVFS）

根据当前负载动态调整 CPU 的频率和电压：

| 场景 | 频率 | 电压 | 功耗 |
|---|---|---|---|
| 音频处理中 | 200 MHz | 1.1V | 高 |
| 等待蓝牙事件 | 50 MHz | 0.9V | 中 |
| 空闲 | 睡眠 | — | 极低 |

```c
// 根据负载调整频率
void adjust_clock(void) {
    if (audio_active) {
        clk_set_freq(CPU_CLK, 200000000);  // 200MHz
    } else if (bt_connected) {
        clk_set_freq(CPU_CLK, 50000000);   // 50MHz
    } else {
        power_enter_sleep();                // 进入睡眠
    }
}
```

### 2.3 FreeRTOS Tickless Idle：空闲时省电

FreeRTOS 默认每个 Tick（1ms）都会唤醒 CPU 检查有没有就绪任务。如果下一个任务在 100ms 后才就绪，这 100 次唤醒都白白浪费。

**Tickless Idle** 让 CPU 一次性睡到下一个任务需要运行的时间：

```c
// FreeRTOSConfig.h
#define configUSE_TICKLESS_IDLE 1

// 效果：如果所有任务都在等待，CPU 进入睡眠直到最近的任务需要运行
// 比如最近的任务 100ms 后才就绪，CPU 就睡 100ms，不再每 1ms 醒一次
```

### 2.4 WQ7036A 的低功耗策略

WQ7036A 作为音频 SoC，功耗管理非常关键（耳机/眼镜类产品电池很小）：

| 策略 | 说明 |
|---|---|
| 核级关断 | 不需要 DCORE 音频处理时，完全关闭 DCORE 电源 |
| 外设时钟门控 | 逐个外设控制时钟使能 |
| 音频 DMA 低功耗 | DMA 搬运音频数据时 CPU 进入睡眠 |
| 蓝牙低功耗模式 | BLE 广播间隔拉长，减少射频活动时间 |
| KWS 低功耗唤醒 | DCORE 上的 KWS（唤醒词检测）用极低功耗运行，检测到唤醒词才唤醒 ACORE |

### 2.5 功耗测算

设计电池供电产品时，需要做功耗预算：

```
示例：蓝牙耳机功耗预算

| 状态        | 电流    | 占比  | 加权平均 |
|-------------|---------|-------|----------|
| 播放音乐     | 15 mA   | 30%   | 4.5 mA   |
| 待机（BT连接）| 2 mA    | 50%   | 1.0 mA   |
| 深度睡眠     | 50 μA   | 20%   | 0.01 mA  |
|-------------|---------|-------|----------|
| 加权平均     |         |       | 5.51 mA  |

电池容量：200 mAh
预计续航：200 / 5.51 ≈ 36 小时
```

**实测方法**：
- 串联万用表/电流表到电源线路
- 用电流探针 + 示波器看瞬态电流波形
- 用专用功耗分析仪（如 Otii Arc）

### 2.6 常见坑

1. **忘了关某个外设的时钟**：一个没用的外设可能消耗几 mA。
2. **GPIO 悬空**：未配置的引脚可能来回跳变，增加功耗。不用时配为模拟输入或输出。
3. **上拉/下拉电阻耗电**：内部弱上拉在引脚拉低时持续耗电。
4. **睡眠后被错误中断唤醒**：开了太多中断使能，被无关中断频繁唤醒。

## 第三层：深入扩展

### 3.1 电源门控（Power Gating）

比时钟门控更彻底——直接切断某个模块的电源：

```
时钟门控：模块还在供电，只是没有时钟 → 静态功耗仍然存在
电源门控：模块完全断电 → 静态功耗几乎为 0
```

WQ7036A 的 DCORE（DSP）就使用了电源门控：不需要音频处理时，DCORE 完全断电。

### 3.2 低功耗蓝牙（BLE）的功耗优化

| 参数 | 影响 | 优化方向 |
|---|---|---|
| 广播间隔 | 间隔越长越省电 | 非连接状态：100ms~10s |
| 连接间隔 | 间隔越长越省电 | 连接状态：7.5ms~4s |
| Slave Latency | 从设备可以跳过几次事件 | 增大 latency 省电 |
| TX Power | 发射功率越高越耗电 | 够用就行，不必最大 |

### 3.3 音频场景的低功耗权衡

音频系统面临一个矛盾：实时性要求高（I2S 数据不能断） vs 功耗要低。

**解决策略**：

1. **大 DMA 缓冲**：DMA 一次搬运较多数据，CPU 睡久一点再处理。
2. **DCORE 独立运行**：音频算法在 DSP 上跑，ACORE 可以长时间睡眠。
3. **VAD（Voice Activity Detection）**：检测到有人说话才启动完整的音频管道，没声音时只跑低功耗的 KWS。

### 3.4 常见面试题

- **为什么降电压比降频率更省电？** 因为动态功耗 P = CV²f，电压是平方关系。
- **Sleep 和 Deep Sleep 的区别？** Sleep 保留全部 RAM 和 CPU 状态，唤醒快；Deep Sleep 只保留部分，唤醒慢但更省电。
- **什么是 Tickless Idle？** RTOS 不再每个 Tick 唤醒 CPU，而是睡到最近的任务需要运行的时间。
- **电池供电产品怎么做功耗预算？** 列出所有状态的电流和占比，算加权平均，除以电池容量得续航。
