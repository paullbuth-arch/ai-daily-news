# 数据结构与状态机

**一句话结论（20% 核心）**：嵌入式里 80% 的业务逻辑都可以用**数组、链表、队列（环形缓冲区）、状态机**这四种结构表达清楚。其中状态机是嵌入式最重要的设计模式——协议解析、按键处理、设备管理，全靠它。

---

## 第一层：核心认知

### 1.1 为什么数据结构在嵌入式里特别重要？

| 场景 | 需要的数据结构 |
|---|---|
| UART 收到的数据暂存 | 环形缓冲区（Ring Buffer） |
| 任务间传递消息 | 队列（Queue） |
| 管理多个设备/连接 | 链表（Linked List） |
| 解析协议帧 | 状态机（State Machine） |
| 按键去抖 + 长短按判断 | 状态机 |
| 定时器管理 | 有序链表 / 最小堆 |

### 1.2 核心数据结构速查

| 结构 | 特点 | 嵌入式典型场景 |
|---|---|---|
| **数组** | 连续、索引快、大小固定 | 查找表、缓冲池、配置表 |
| **链表** | 动态插入删除、不连续 | 任务列表、内存块管理、定时器 |
| **队列** | FIFO，先进先出 | ISR 与任务间传数据 |
| **环形缓冲区** | 首尾相接的队列 | UART/SPI 收发缓冲 |
| **状态机** | 事件驱动、状态跳转清晰 | 协议解析、按键、设备控制 |
| **栈** | LIFO，后进先出 | 函数调用、表达式求值 |

### 1.3 状态机是什么？

**费曼类比**：状态机就像红绿灯。

```
绿灯 ──[倒计时结束]──→ 黄灯 ──[倒计时结束]──→ 红灯 ──[倒计时结束]──→ 绿灯
```

- **状态（State）**：绿灯、黄灯、红灯。
- **事件（Event）**：倒计时结束。
- **跳转（Transition）**：从一个状态到另一个状态。

**更复杂的例子**：按键处理状态机

```
IDLE（空闲）──[按下]──→ PRESSED（按下）
PRESSED ──[释放，<500ms]──→ IDLE（短按事件）
PRESSED ──[持续按住，>500ms]──→ LONG_PRESSED（长按事件）
LONG_PRESSED ──[释放]──→ IDLE（长按释放事件）
```

### 1.4 最小代码示例

```c
// 最简单的状态机：用 switch-case
typedef enum {
    STATE_IDLE,
    STATE_BUSY,
    STATE_DONE
} state_t;

state_t state = STATE_IDLE;

void state_machine_run(event_t ev)
{
    switch (state) {
    case STATE_IDLE:
        if (ev == EV_START) {
            state = STATE_BUSY;
            start_work();
        }
        break;
    case STATE_BUSY:
        if (ev == EV_FINISH) {
            state = STATE_DONE;
            notify_complete();
        }
        break;
    case STATE_DONE:
        if (ev == EV_RESET) {
            state = STATE_IDLE;
        }
        break;
    }
}
```

### 1.5 如果只记得一件事

> 嵌入式最常用的数据结构是环形缓冲区（ISR↔任务传数据）和状态机（协议解析/按键/设备控制）。状态机的核心是"在什么状态下，收到什么事件，跳转到什么状态"。

## 第二层：实战理解

### 2.1 环形缓冲区（Ring Buffer）：ISR 安全的队列

环形缓冲区是嵌入式中**最重要的数据结构之一**，常用于中断和任务之间的数据传递。

**核心思想**：用固定大小的数组，首尾相接形成环。用 `head`（写入位置）和 `tail`（读取位置）两个指针管理。

```c
#define RBUF_SIZE 256          // 必须是 2 的幂
#define RBUF_MASK (RBUF_SIZE - 1)

typedef struct {
    uint8_t  buf[RBUF_SIZE];
    volatile uint32_t head;    // 写入方（ISR）修改
    volatile uint32_t tail;    // 读取方（任务）修改
} rbuf_t;

static inline bool rbuf_is_empty(rbuf_t *rb) {
    return rb->head == rb->tail;
}

static inline bool rbuf_is_full(rbuf_t *rb) {
    return ((rb->head - rb->tail) & RBUF_MASK) == 0
           && rb->head != rb->tail;
}

// ISR 中调用：写入一个字节
bool rbuf_put(rbuf_t *rb, uint8_t data) {
    if (rbuf_is_full(rb)) return false;
    rb->buf[rb->head & RBUF_MASK] = data;
    rb->head++;  // 自然溢出，靠 MASK 回绕
    return true;
}

// 任务中调用：读取一个字节
bool rbuf_get(rbuf_t *rb, uint8_t *data) {
    if (rbuf_is_empty(rb)) return false;
    *data = rb->buf[rb->tail & RBUF_MASK];
    rb->tail++;
    return true;
}

// 可用数据量
uint32_t rbuf_available(rbuf_t *rb) {
    return rb->head - rb->tail;
}
```

**为什么这个实现是 ISR 安全的？**

- `head` 只由 ISR 写，任务只读。
- `tail` 只由任务写，ISR 只读。
- 双方都只做一次原子写入（`head++` 或 `tail++`），不需要加锁。
- 前提是 `head` 和 `tail` 都是 32 位整数（在 32 位 CPU 上一次读写是原子的）。

**典型使用**：

```c
rbuf_t uart_rx_buf;

// UART 接收中断
void uart_isr(void) {
    uint8_t byte = UART_DR;
    rbuf_put(&uart_rx_buf, byte);
}

// 处理任务
void process_task(void *p) {
    uint8_t byte;
    for (;;) {
        while (rbuf_get(&uart_rx_buf, &byte)) {
            // 处理收到的字节
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### 2.2 函数指针实现的状态机

比 switch-case 更优雅、更易扩展的写法：

```c
// 定义状态处理函数类型
typedef void (*state_handler_t)(event_t ev);

// 每个状态一个处理函数
static void state_idle(event_t ev) {
    if (ev == EV_START) {
        current_state = STATE_BUSY;
        start_work();
    }
}

static void state_busy(event_t ev) {
    if (ev == EV_FINISH) {
        current_state = STATE_DONE;
        notify_complete();
    } else if (ev == EV_CANCEL) {
        current_state = STATE_IDLE;
        cancel_work();
    }
}

static void state_done(event_t ev) {
    if (ev == EV_RESET) {
        current_state = STATE_IDLE;
    }
}

// 状态表
static state_handler_t state_table[] = {
    [STATE_IDLE] = state_idle,
    [STATE_BUSY] = state_busy,
    [STATE_DONE] = state_done,
};

// 统一调度
void fsm_dispatch(event_t ev) {
    state_table[current_state](ev);
}
```

### 2.3 状态表驱动的协议解析

状态机最常见的应用是**解析协议帧**。以简单的帧格式为例：

```
帧格式：[0xAA] [LEN] [DATA...] [CHECKSUM] [0x55]

状态跳转：
WAIT_HEADER → 收到 0xAA → READ_LEN
READ_LEN    → 读到长度 → READ_DATA
READ_DATA   → 读够长度 → READ_CHECKSUM
READ_CHECKSUM → 校验正确 → WAIT_TAIL
WAIT_TAIL   → 收到 0x55 → 帧完整，处理 → WAIT_HEADER
任何状态收到非法数据 → WAIT_HEADER（重新开始）
```

```c
typedef enum {
    PARSE_WAIT_HEADER,
    PARSE_READ_LEN,
    PARSE_READ_DATA,
    PARSE_READ_CHECKSUM,
    PARSE_WAIT_TAIL,
} parse_state_t;

static parse_state_t parse_state = PARSE_WAIT_HEADER;
static uint8_t  frame_buf[256];
static uint8_t  frame_len;
static uint8_t  frame_idx;

bool parse_byte(uint8_t byte)
{
    switch (parse_state) {
    case PARSE_WAIT_HEADER:
        if (byte == 0xAA) {
            parse_state = PARSE_READ_LEN;
        }
        break;

    case PARSE_READ_LEN:
        frame_len = byte;
        frame_idx = 0;
        parse_state = PARSE_READ_DATA;
        break;

    case PARSE_READ_DATA:
        frame_buf[frame_idx++] = byte;
        if (frame_idx >= frame_len) {
            parse_state = PARSE_READ_CHECKSUM;
        }
        break;

    case PARSE_READ_CHECKSUM:
        if (byte == calc_checksum(frame_buf, frame_len)) {
            parse_state = PARSE_WAIT_TAIL;
        } else {
            parse_state = PARSE_WAIT_HEADER;  // 校验失败
        }
        break;

    case PARSE_WAIT_TAIL:
        parse_state = PARSE_WAIT_HEADER;
        if (byte == 0x55) {
            // 帧完整，处理 frame_buf
            handle_frame(frame_buf, frame_len);
            return true;
        }
        break;
    }
    return false;
}
```

### 2.4 链表的嵌入式用法

嵌入式中常用**侵入式链表**（Intrusive List），把链表节点嵌入到结构体内部：

```c
// 链表节点（嵌入到业务结构体中）
typedef struct list_node {
    struct list_node *next;
    struct list_node *prev;
} list_node_t;

// 业务结构体
typedef struct {
    list_node_t node;    // 链表节点放在最前面
    uint32_t    id;
    char        name[32];
} device_t;

// 初始化链表
void list_init(list_node_t *head) {
    head->next = head;
    head->prev = head;
}

// 插入到链表尾部
void list_add_tail(list_node_t *head, list_node_t *new_node) {
    new_node->prev = head->prev;
    new_node->next = head;
    head->prev->next = new_node;
    head->prev = new_node;
}

// 遍历链表
list_node_t *pos;
for (pos = head.next; pos != &head; pos = pos->next) {
    device_t *dev = (device_t *)pos;  // 类型转换
    printf("Device: %s (id=%lu)\n", dev->name, dev->id);
}
```

**侵入式链表的优势**：
- 不需要额外的 `malloc` 来分配节点。
- 一个结构体可以同时挂在多个链表中。
- Linux 内核的 `list_head` 就是这种设计。

### 2.5 常见坑

1. **环形缓冲区大小不是 2 的幂**：位掩膜 `& MASK` 无法正确回绕。
2. **状态机忘记处理 default**：收到未知事件时状态不变但也没报错。
3. **链表操作忘记更新双向指针**：删除节点时只更新了 `next` 没更新 `prev`。
4. **ISR 中用了不可重入的函数**：如在 ISR 中调用 `malloc`、`printf`。

### 3.1 分层状态机（HSM, Hierarchical State Machine）

当状态很多时，用层次结构简化：

```
Playing（父状态）
├── Playing_Audio（子状态）
├── Playing_BT（子状态）
└── Playing_Local（子状态）

Paused（父状态）
```

子状态自动继承父状态的处理。如果子状态没有处理某个事件，自动冒泡到父状态处理。

```c
// 分层状态机的核心思路
void hsm_dispatch(event_t ev) {
    state_handler_t handler = current_state;
    
    while (handler != NULL) {
        if (handler(ev) == EVENT_HANDLED) {
            return;
        }
        handler = handler->parent;  // 冒泡到父状态
    }
    // 没有任何状态处理这个事件
}
```

### 3.2 批量数据传输的环形缓冲区

当需要一次传输多个字节时（如 UART 一次发送整条消息），支持批量操作：

```c
// 批量写入
uint32_t rbuf_put_bulk(rbuf_t *rb, const uint8_t *data, uint32_t len) {
    uint32_t space = RBUF_SIZE - rbuf_available(rb);
    if (len > space) len = space;  // 最多写可用空间大小
    
    for (uint32_t i = 0; i < len; i++) {
        rb->buf[(rb->head + i) & RBUF_MASK] = data[i];
    }
    rb->head += len;
    return len;
}

// 批量读取（零拷贝思路：返回指针和连续长度）
uint32_t rbuf_peek(rbuf_t *rb, uint8_t **ptr) {
    uint32_t avail = rbuf_available(rb);
    uint32_t tail_idx = rb->tail & RBUF_MASK;
    uint32_t contiguous = RBUF_SIZE - tail_idx;
    
    *ptr = &rb->buf[tail_idx];
    return (contiguous < avail) ? contiguous : avail;
}

void rbuf_consume(rbuf_t *rb, uint32_t len) {
    rb->tail += len;
}
```

### 3.3 定时器的有序链表管理

多个定时任务用有序链表管理，按到期时间排序：

```c
typedef struct timer_node {
    list_node_t node;
    uint32_t    expire_tick;
    void        (*callback)(void *arg);
    void        *arg;
} timer_node_t;

// 插入时按到期时间排序
void timer_add(timer_node_t *timer) {
    list_node_t *pos;
    for (pos = timer_list.next; pos != &timer_list; pos = pos->next) {
        timer_node_t *t = container_of(pos, timer_node_t, node);
        if (timer->expire_tick < t->expire_tick) {
            list_insert_before(&t->node, &timer->node);
            return;
        }
    }
    list_add_tail(&timer_list, &timer->node);
}

// Tick 中断中检查
void timer_tick(void) {
    current_tick++;
    while (!list_empty(&timer_list)) {
        timer_node_t *first = container_of(timer_list.next, timer_node_t, node);
        if (first->expire_tick <= current_tick) {
            list_remove(&first->node);
            first->callback(first->arg);
        } else {
            break;  // 后面的到期时间更晚
        }
    }
}
```

### 3.4 常见面试题

- **环形缓冲区为什么大小要是 2 的幂？** 为了用位掩膜（`& MASK`）代替取模（`% SIZE`），速度快得多。
- **状态机和 if-else 的区别？** 状态机显式定义了所有状态和跳转，更清晰、更易测试、不易遗漏。
- **侵入式链表和普通链表的区别？** 侵入式把节点嵌入业务结构体，不需要额外 malloc；普通链表节点包含数据指针。
- **怎么让环形缓冲区在单生产者单消费者场景下无锁？** 生产者和消费者分别只修改 head 或 tail，且用 32 位原子写入。
