# WQ7036AX 芯片

**一句话结论（20% 核心）**：WQ7036AX 是一颗三核音频 SoC——ACORE（RISC-V）管应用逻辑，BCORE（RISC-V）管蓝牙射频，DCORE（Xtensa HiFi5）管音频 DSP。你写的代码 95% 跑在 ACORE 上。

---

## 第一层：核心认知（必须先看懂）

### 1.1 费曼类比：三个专业员工

WQ7036AX 不是一颗普通的单核芯片，而是三个"专业员工"各司其职：

| 核 | 架构 | 角色 | 类比 |
|---|---|---|---|
| **ACORE** | RISC-V | 应用核，跑 FreeRTOS | **CEO**——做决策、管外设、协调全局 |
| **BCORE** | RISC-V | 蓝牙核，跑 BT Controller 固件 | **专职翻译**——只负责和手机蓝牙通信 |
| **DCORE** | Xtensa HiFi5 | 音频 DSP 核 | **专业调音师**——只做降噪、编码等音频算法 |

**为什么分三个核？** 因为蓝牙协议栈需要在微秒级响应，音频 DSP 需要大量乘加运算。如果全挤在一个核上，一个卡顿就会导致蓝牙断连或音频爆音。

**核间怎么通信？** 通过共享内存 + 软中断（IPC）。详见 [[ipc-multicore-多核通信与IPC]]。

### 1.2 WQ7036AX 管什么、不管什么？

```
WQ7036AX 负责:                    WQ7036AX 不负责:
  ✅ BLE 连接手机                    ❌ WiFi（V881 负责）
  ✅ 4 路 PDM 麦采集                  ❌ 摄像头/TOF（V881）
  ✅ DSP 音频处理（降噪/编码）         ❌ eMMC 存储（V881）
  ✅ 双扬声器 I2S 输出                ❌ USB Type-C（V881）
  ✅ 光传感器 + 充电 IC（I2C）        ❌ 视频编码（V881）
  ✅ 按键/LED 控制（GPIO）            ❌ 显示屏（V881）
  ✅ UART 与 V881 通信
```

**判断原则**：硬件连在谁身上，谁就负责。麦克风、扬声器、按键、LED、传感器都在 WQ7036AX 上；摄像头、TOF、WiFi、屏幕都在 V881 上。

### 1.3 引脚功能速查（reGlasses 用到的）

**通信接口：**

| 协议 | 引脚 | 对端 | 用途 |
|------|------|------|------|
| UART TX | GPIO50 (C17) | V881 RX | 所有跨芯片命令和数据 |
| UART RX | GPIO51 (A16) | V881 TX | |
| I2C #1 | A10/A9 | ELM2713 光传感器 | 环境光 + 佩戴检测 |
| I2C #2 | B8/B7 | 充电 IC | 充电状态、电量 |
| I2S #1 | A17/B15/B16/D17 | V881 | 双向音频数据 |
| I2S #2 | AMP_I2S_* | MAX98357A 功放 | 扬声器输出 |

**控制与状态：**

| 功能 | 引脚 | 类型 |
|------|------|------|
| KEY_1 (功能键A) | M14 | 输入，上拉 |
| KEY_2 (功能键B) | M5 | 输入，上拉 |
| KEY_3 (电源键) | N6 | 输入，上拉 |
| LED_R/G/B | N10/M10/N11 | 输出 |
| LS_INT（光感中断） | M12 | 输入中断 |
| PS_EN（电源使能） | J9 | 输出 |
| BT-WK-V881（唤醒V881） | M13 | 输出 |

### 1.4 电源域

| 电源 | 电压 | 用途 |
|------|------|------|
| VDD12 | 1.2V | 核心数字逻辑 |
| AVDD33_AON | 3.3V | 模拟电路，常开 |
| VBAT_TWS | 电池电压 | 主供电 |

### 1.5 如果只记得一件事

> WQ7036AX = 三核异构 SoC。ACORE 跑你的代码（FreeRTOS + 应用逻辑），BCORE 管蓝牙，DCORE 管音频。硬件连在谁身上谁就负责——这是判断命令该本地执行还是转发 V881 的唯一标准。

## 第二层：实战理解

### 2.1 启动顺序

```
上电 → ACORE 先启动（初始化硬件、IPC）
         │
         ├→ 启动 BCORE（加载蓝牙固件）
         └→ 启动 DCORE（加载 DSP 固件）
```

ACORE 是主控，负责拉起其他两个核。启动代码在 `wqcore/components/startup/` 下。

### 2.2 你的代码跑在哪？

95% 在 ACORE 上。需要音频处理时，通过 IPC 调用 DCORE 的 DSP 功能——你不需要写 DSP 代码，只需调用 audio_service API：

```c
// 启动音频采集（底层自动调度 DCORE 做 DSP 处理）
aud_sv_start_capture(&cfg);

// 注册回调：收到编码后的音频帧
aud_sv_register_data_callback(on_audio_data);
```

### 2.3 常见坑

| 问题 | 现象 | 根因 |
|---|---|---|
| 引脚复用冲突 | 某个外设不工作 | 两个外设分配到了同一个 GPIO 引脚 |
| 电源域忘使能 | 外设无法访问 | 外设的电源域没打开 |
| 时钟没配 | 外设通信乱码 | 忘了给外设模块使能时钟 |
