# 数据流：手机指令到 V881

## 一句话理解

手机 APP 发出的一条指令（比如"开始录制"），要经过 **BLE 空中传输 → WQ7036AX 解包 → 重新打包 → UART 发送** 四个阶段才能到达 V881。WQ7036AX 就是中间的"翻译官"。

## 完整路径

```
Step 1: 手机 APP 构造 WQ Protocol 帧
Step 2: 通过 BLE GATT Write 发送到 WQ7036AX
Step 3: WQ7036AX 解包 → 判断路由 → 重新打包为 [[UART 命令协议]] 帧
Step 4: 通过 UART 发送到 V881
Step 5: V881 处理 → 响应原路返回
```

## Step 1：手机 APP 构造帧

手机 APP 用 [[WQ Audio Protocol]] 格式打包一条"开始录制"指令：

```
Frame Header (7B):
  sync_word = 0x5751
  frame_type = REQ (1)
  need_ack = 1
  seq_number = 42

Message Header (4B):
  service_type = SERVICE_TYPE_CONTROL (0x04)
  command_id = CTRL_RECORD_START_REQ (0x01)
  payload_len = 4

Payload (4B):
  camera_mask = 0x07 (广角+长焦+TOF)
  max_duration_s = 0 (不限)
  audio_enable = 1
```

总帧大小 = 7 + 4 + 4 = 15 字节。

## Step 2：BLE GATT Write

手机通过 BLE GATT 的 **C1 Device Control Characteristic** 写入这 15 字节。

```
手机 APP → BLE Write (C1) → 空中传输 (~15ms) → WQ7036AX BLE 控制器接收
```

**在 SDK 中**：`ota_transport_ble.c` 中查看 `gatt_connection_callback` 和 `write_callback`

## Step 3：WQ7036AX 解包 + 路由

WQ7036AX 的 BLE 收到数据后：

```c
// write_callback 被调用
static void write_callback(uint8_t index, const uint8_t *data, uint16_t len)
{
    // ① 解包 WQ Protocol 帧
    wq_proto_pkt_t pkt;
    wq_proto_pkt_unpack(&pkt, data, len);

    // ② 根据 service_type 路由
    switch (pkt.msg_header.service_type) {
    case SERVICE_TYPE_CONTROL:
        // CTRL_RECORD_START → 转发给 V881
        forward_to_v881_via_sttp(&pkt);
        break;
    case SERVICE_TYPE_TRANS_UP:
        // 音频上行 → 本地处理
        handle_audio_up(&pkt);
        break;
    }
}
```

**路由规则**（详见 [[reGlasses 跨芯片指令转发]]）：

| 命令 | 执行位置 | 原因 |
|------|----------|------|
| RECORD_START | **V881** | 摄像头在 V881 上 |
| TAKE_PHOTO | **V881** | 同上 |
| TOF_ON/OFF | **V881** | TOF 在 V881 上 |
| VOICE_ON/OFF | **WQ 本地** | 麦克风在 WQ7036AX 上 |
| STATUS_QUERY | WQ + V881 | 合并两端状态 |

## Step 4：通过 UART 命令协议发送到 V881

WQ7036AX 把 WQ Protocol 的 payload **重新打包**为 [[UART 命令协议]] 帧：

```
UART CMD Frame:
  [0xAA] [len] [cmd=VOICE_START] [seq] [session_id 4B] [xor_crc]
  (2+1+4+1 = 8 bytes total)
```

通过 UART TX (GPIO50) 发出。

**在 SDK 中**：`app_uart_cmd.c` 中查看 `uart_cmd_send`

## Step 5：V881 响应 → 原路返回

```
V881: 收到 UART CMD 帧 → 解包 → 启动 ASR → 打包 VOICE_RESULT 响应
  │
  │ UART CMD (VOICE_RESULT, ACK, session_id=42)
  ↓
WQ7036AX: 收到 UART CMD 响应 → 解包 → 打包为 WQ Protocol RSP
  │
  │ BLE GATT Notify (C2: Device Status)
  ↓
手机 APP: 收到 EVT_RECORD_STARTED → UI 显示"录制中"
```

## 完整时序图

```
手机 APP            WQ7036AX              V881
  │                    │                    │
  │── BLE Write ──────→│                    │
  │  WQ Protocol       │                    │
  │  CTRL_RECORD_START │                    │
  │  (15 bytes)        │                    │
  │                    │                    │
  │                    │ wq_proto_pkt_unpack()
  │                    │ → service=CONTROL
  │                    │ → 需要转发
  │                    │                    │
  │                    │── UART CMD ───────→│
  │                    │  VOICE_START       │
  │                    │  session_id=42     │
  │                    │                    │
  │                    │   (V881 启动 ASR     │
  │                    │    开始识别)         │
  │                    │                    │
  │                    │←─ UART CMD ACK ───│
  │                    │  cmd=0x7F          │
  │                    │                    │
  │                    │ wq_proto_pkt_pack()
  │                    │ → RSP + EVT_RECORD_STARTED
  │                    │                    │
  │← BLE Notify ──────│                    │
  │  Device Status     │                    │
  │  EVT_RECORD_STARTED│                    │
  │                    │                    │
  │  UI: "录制中" 🔴    │                    │
```

## 每一步的延迟

| 阶段 | 延迟 |
|------|------|
| BLE Write (空中) | ~15ms |
| WQ7036AX 解包 | <1ms |
| UART CMD 发送 | <1ms |
| V881 ASR 处理 | 50-500ms (语音识别) |
| UART CMD 响应 | <1ms |
| BLE Notify | ~15ms |
| **总计** | **~100-250ms** |

#flashcard
问：一条"开始录制"指令从手机到 V881 经过哪几个阶段？
答：①手机打包 WQ Protocol ②BLE Write 发送 ③WQ7036AX 解包+路由 ④重新打包 UART CMD 帧 ⑤UART 发送到 V881。

问：WQ7036AX 收到 CTRL_RECORD_START 后是本地执行还是转发 V881？为什么？
答：转发 V881。因为摄像头硬件连接在 V881 上，WQ7036AX 没有摄像头驱动，必须让 V881 来启动录制。
